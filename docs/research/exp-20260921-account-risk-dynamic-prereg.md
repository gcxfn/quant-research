## 3. 变量：账户级暴露系数 E_t 与四档

`E_t ∈ {0.90, 0.40}` 与账户级三档家族沿用上位预登记 §2 及 R8/R9 登记值（e_on 0.90、e_low 0.40、D60-8 的 re-arm ≤4%、PDD-10 的 re-arm ≤5%），本轮**不搜索**其他档位、阈值、窗口或降仓比例。

| 档 | 机制 | 触发条件（只用本账户已完成收盘观测） | 恢复条件 | 确认/冷却 |
|---|---|---|---|---|
| D0 控制组 | 恒定 `E=0.90` | 无 | — | — |
| D1 单日损失 | 单会话权益收益 `r_t = E_t/E_{t-1} − 1 ≤ −3.00%` | `r_t > −3.00%` | 2 会话 / 3 会话 |
| D2 阶段回撤 | 距**最近 60 个已完成会话**峰值回撤 `dd60 > 8.00%`（窗口不足 60 时用已有全部） | `dd60 ≤ 4.00%` | 2 会话 / 3 会话 |
| D3 高水位回撤 | 距**全时点权益高水位**回撤 `dd > 10.00%` | `dd ≤ 5.00%` | 2 会话 / 3 会话 |

- 三档共享降档语义：降档即时（观测到即本决策点生效），升档必须满足恢复条件连续 **2 个已完成会话**且距降档已过 **3 个已完成会话**冷却期；计数单位是"已判定会话"（不同 asof 观测日），不是决策点——11:30 重读前一收盘不重复计数、也不重置。
- 恢复不设中间档位，只回到 0.90。
- `D1` 的 3.00% 是运行前一次性写死的圆整值（不来自本组合路径的分位、不做网格），触发频率作为结果报告。
- 首次观测口径：参考基准建立在**第一个已完成收盘观测**上（`dd=0`、无可见损失 → NORMAL），与上位预登记 C2"参考峰从本 run 首个权益观测开始"一致。
- 数据不足（尚无任何已完成收盘观测）→ `insufficient_data`：**不新增进攻仓位**（fail-closed），不产生降仓腿。
- 状态语义只有两种用途：`normal` → 新进攻仓位按 0.90 目标；`reduced` → 新进攻仓位按 0.40 目标；`insufficient_data` → 不新增。本轮的 D0–D3 都**不注册硬止损**，"暂停新增进攻"只由数据缺失触发（因此不产生新的账户级暂停阈值）。

## 4. 意图映射（运行前写死的实现约定）

1. **比例缩放**：基准进攻目标权重 0.10（即 E=0.90 口径）乘以 `E_t/0.90` → 正常 `0.10000`、降档 `0.04444`。防御层/现金不动（本载体无防御腿，释放的资金留在现金）。
2. **新席位**（池内成员且未持有）：`buy` + `target_weight`（缩放后目标），逐半日重发，与 F3R3 相同。
3. **降档腿**（`normal→reduced` 转移时对每个已持有成员）：`sell` + `target_weight=0.04444`，`intent='profit'`。语义登记：账户级降仓是**不假设成交的半日限价单**——半日未成交即失效，由下一决策点按新锚价显式重发；**不使用** `intent='risk'` 的 K=3 开盘强制兜底，因为账户级降仓不是单标的止损、不得强迫成交（AGENTS §1"止盈类订单到期失效，不得假设必然成交"的保守口径同样适用）。只要处于 `reduced` 且该成员权重高于目标 0.005（账户权益占比）以上，就持续重发。
4. **恢复腿**（`reduced→normal` 转移时对每个低于目标的已持有成员）：`buy` + `target_notional = (0.10000 − w_cur) × equity_snapshot`，逐半日重发直到补齐（`w_cur ≥ 目标 − 0.005`）或该成员退出池。
5. **normal 且无待补**：对已持有成员不发任何意图（与 D0/F3R3 完全一致），因此不会出现未登记的"按目标再平衡"行为。
6. **权重口径**：`w_cur = 股数 × 决策点标记价 / equity_snapshot`。标记价按引擎同一口径复算：上午决策用当日已完成 am 收盘、无 am 栏（停牌）用最后成交收盘；下午决策用当日或之前最后成交的官方收盘。每个决策点必须通过账本身份校验 `cash + pending_am_to_pm + pending_next_day + Σ 股数×标记价 == ledger['equity_snapshot']`（相对容差 1e-9），不通过即 fail-closed 终止运行。
7. **额度约束**：单只 25%、总仓 100%、T+1、涨跌停、停牌、整手、现金约束全部由引擎执行；宿主不绕过、不改写。
