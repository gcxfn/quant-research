## 4. 全量 40,079 行吞吐/成本外推（不确定度大，仅供量级参考）

- 吞吐三情景（均标注不确定度）：① 按本次代理会话实测 3.7 s/行 → 单流约 40 小时，不适合全量；② API 单流按 2–5 s/行 → 21–54 小时；③ API 并发 10–20（受账户速率限制约束，本环境曾因此中断过一次）→ **约 1–5.5 小时**，或改用 batch API 过夜完成。无论何者，必须沿用逐批落盘断点续跑，并增加批内每 25–50 行的 partial 落盘。

## 5. 质量风险与改进建议

1. **原文质量**：change_reason 存在少量乱码/改写痕迹（混入英文标识符、语句不通、尾部截断），本次按原文逐字引用不受影响，但会推高 other/low；建议全量前加"原文质量标记"字段，乱码行不进研究判据。
2. **无语义金标**：本次只验证了程序性一致（quote 子串 100%、词表闭合），**未验证语义标注准确率**（无人工双人金标）。全量前建议抽 50–100 行人工复核 primary 语义一致率，目标 ≥90% 再放行。
3. **supports_direction 规则**：-1 率 3.8% 混合了"减亏类改善原因"（语义正确）与"type 与文本疑似错配"（数据质量）。v2 建议拆成 `reason_vs_type` 与 `data_quality_flag` 两个维度，避免混用。
4. **低信息行**：core_ops(30)+other(20)=8.3% 无具体驱动；v2 可为 other 增加自由文本标签字段（不进封闭词表）以保留信息。
5. **secondary 证据未强制程序验证**（checker 只验证 key_quote）；若研究要用 secondary，需增加 `secondary_quote` 字段并同样 100% 校验。
6. **词表缺口**：政策类（集采/补贴退坡/限电）、天气灾害均落入 other；fx 作为 primary 仅 1 行。若全量后 other 率 >8%，评估 v2 增码（policy/weather/base_effect），并重写 pilot 对比。
7. **小层代表性**：续盈（787）、不确定（535）层样本 15+11 行，比例估计的置信区间较宽；pilot 分布只作方向参考，关键率值以全量为准。
8. **断点续跑**：已实现"每批落盘+行数与校验通过即跳过"，本次为完整首跑未触发恢复路径；全量必须先做一次人为中断-恢复演练再上线。
