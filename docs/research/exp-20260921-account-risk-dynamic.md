## 3. 机制结论（只对机制发言）

1. **"账户级降仓能否降低组合回撤"有条件的答案是肯定，但档位差异极大。**
   - **单日损失（D1）证伪**：3% 单会话阈值在该载体（95% 平均敞口、10 只等权席位）上变成高频开关——41 次降档、41 次恢复且**每次都恰好停满 3 会话冷却下限**（即"3 会话定时器"而非风险判别）、换手 9.93→14.57、成交 1093→1863 笔、费用 +5,893 元，而最大回撤反而从 −39.50% 加深到 −45.18%，净年化掉 5.84pp。省÷丢 = −0.97，即"既没省回撤又丢了反弹"。
   - **阶段回撤（D2）方向正确但量级不足**：60 会话峰 8% 阈值把回撤压浅 1.36pp，代价 3.86pp 年化（省÷丢 0.35）；54.8% 的判定会话处于降仓，平均敞口 65.4%。
   - **高水位回撤（D3）是本轮唯一"划算"的机制**：回撤 −39.50%→−29.86%（省 9.64pp），年化只丢 2.04pp（省÷丢 **4.73**，与 R8 §5 日频风控首次出现 >1 的比值同向），最差年份 2018 从 −28.78% 改善到 −15.74%。
2. **D3 的"省回撤"来自一次不再反转的降档，不是可重复的风险控制**：全期只有 2 次降档——2015-05-06（10 会话后恢复）与 2015-06-26，后者**直到 2020 年底都没有恢复**（高水位从未回到 5% 以内），此后 2016–2020 每年 243–244 个判定会话（合计占 92.7%）都停在降档，平均敞口 44.7%、平均现金 55.1%。也就是说 −9.64pp 的回撤节省来自**样本量为 1 的 2015 年 6 月事件**，之后是近乎永久性的降杠杆；其最深回撤窗口是 2015-06-12→09-15，与 D1/D2 的（→2019-01-03）不是同一段行情。行为与 R9 记录的 PDD（自身权益峰）机制一致：**触发一次、长期关闭，反弹期同样被削**（2019 年 D3 +11.07% vs 控制组 +29.89%）。D2 同向但更温和（12 次恢复的间隔中位数 58 会话，远高于 3 会话冷却下限）。
3. **四条曲线的八门状态没有改变**：最好的 D3 仍是净年化 6.49%（<10% 目标）、最大回撤 −29.86%（>20% 绝对线），D0/D1/D2 同样未过；本轮**没有产生任何达标候选**，账户级降仓只是"以年化换回撤"的交换率证据。
4. **对主线的含义**：账户级降仓应作为**账户风险层的独立机制**（按预登记阈值、与单标的规则分离）进入后续主线，而不是用来救股票袖套的收益；D3 型（高水位）在交换率上优于 D2 型（阶段峰）优于 D1 型（单日损失），但"长期关闭"的副作用必须在主线里显式评估。

## 4. 意图映射与实现事实（可复核）

- 入场席位：`buy + target_weight = 0.10 × E/0.90`（正常 0.10000，降档 0.04444），逐半日重发，与载体一致。
- 降档腿：`sell + target_weight = 0.04444`、`intent='profit'`——登记为**不假设成交的半日限价单**，未成交即由下一决策点按新锚价显式重发；**未使用** `intent='risk'` 的 K=3 开盘强制兜底（账户级降仓不是单标的止损）。全期 D1/D2/D3 的 K=3 兜底次数与 D0 同为 5 次（全部来自载体自身的席位全退），可证账户级腿没有触发任何强制卖出。
- 恢复腿：`buy + target_notional = (0.10 − w_cur) × equity`（引擎无"补到目标"原语，宿主按 delta 名义额下单），逐半日重发直到补齐或该席位离开池。
- **上下行执行不对称（实测，必须与"按比例缩放"一起读）**：降档腿在 82–97% 的半日成交，而恢复（补仓）腿只有 44.2%/39.3%/16.7% 的腿在当半日成交，且补仓腿只贡献了买入名义的 **D1 29.6%（5.62M/19.01M）、D2 14.3%（1.75M/12.25M）、D3 1.7%（0.13M/7.44M）**，其余由新席位入场（含席位换手后的重发）贡献。即：机制在*计划*上是对称的比例缩放，在*执行*上更接近"降档后靠新席位与换手把敞口补回来，补仓腿只是持续重试的增量"；D3 因长期不恢复，这一差异几乎不影响它的结果，D1 受影响最大（41 次循环的重建 70% 来自新席位）。
- 权重口径：`w_cur = 股数 × 决策点标记价 / equity_snapshot`，标记价按引擎同口径（11:30 用当日已完成 am 收盘、停牌用最后成交收盘；15:00 用当日或之前最后成交官方收盘）复算，并在每个决策点用账本身份式 `cash + 两桶待结算 + Σ 股数×标记价 == equity_snapshot`（相对容差 1e-9）校验；全期 2885 个决策点 × 4 条曲线全部通过，无 fail-closed。
- 无未登记的"再平衡"行为：`normal` 且无待补时对已持有席位不发任何意图（这也是 D0 能与载体逐帧一致的直接原因）。

## 5. 披露与偏差

1. **阈值浮点边界**：冻结规则用的是严格 `dd > 阈值` 与 `dd ≤ re-arm`；像 `1 − 96/100 = 0.040000000000000036` 这类恰好落在边界上的值会按二进制结果判定。本轮实际路径未出现恰好等于 8.0000%/4.0000%/10.0000%/5.0000% 的判定值（合成测试里已改用避开边界的取值）。
2. **增量状态机不发布未来冷却日期**：`cooldown_until` 只在边界会话已被观测后给出（批处理版 `resolve_overlay` 会给出日期）；冷却门槛本身按会话计数、逐位与批处理版一致（`tests/test_account_risk_dynamic.py::test_n4_*` 四档对齐）。
3. **降仓腿的意图类型是对 AGENTS §1 的有意偏离，必须记住**：§1 要求"风险减仓类订单连续三个半日未成交时进入下一半日开盘兜底"，而账户级降仓属于风险减仓；本轮预登记 §4.3 却登记为 `intent='profit'`（半日有效、不兜底、逐决策点重发），理由是 `risk` 意图会被引擎 m3 长期续挂，状态恢复后仍可能把持仓削减回旧的降档目标。事实核对：引擎对"按权重"的 `risk` 卖单兜底是**部分数量**（`band_engine.py` 的 K=3 执行分支 `qty = sell_sh if order_shares is None else min(order_shares, sell_sh)`），所以 `risk` 不会造成整体清仓，§1 的兜底在实现上可用。实测证据（§2 执行事实表）：`profit` 降仓腿在本路径上 82–97% 当半日成交，未成交者在下一决策点重发，**没有出现过"跌市完全无法降仓"**；且该选择只会少成交（保守），因此本轮的省回撤数字应读作**下界**。**主线登记时的正确做法**：按 §1 登记为 `risk`（带部分数量兜底）并另跑一条曲线对照，而不是沿用本轮的 `profit` 口径；在那之前不得把本轮的降档执行率当作主线执行率。
4. **只回放了 ICW 单臂**（预登记 §2 固定），EW 臂只用于构建与 F3R3 相同的 B1(m)/B3′ 基准（B1(m) 净 +1.66%、最大回撤 −64.42%；B3′ 均值 −1.89%，种子 17..36）。
5. **账户级腿的成交与费用计入该曲线的自营账本**（D1 费用 28,138 元 vs D0 22,245 元），换手口径为"年单边买入名义 / 平均权益"。
6. 本轮没有与单标的止损、R 倍数止盈或移动保护线联合调参（载体本身不含这些规则，只有席位离开池的全退 + 引擎 K=3 兜底）。
7. **补仓腿的 `below_min_lot` 噪声（已测量，未修正）**：0.005×权益（≈1000 元）的 `RESIZE_TOLERANCE` 小于部分标的的一手市值，当"距目标不足一手但超过容差"时补仓腿会每个半日重发并被引擎按 `below_min_lot` 没收。实测空单（买单）数：D1 358 / D2 100 / D3 12；对应补仓腿 1288/405/78。经济影响有界（每个席位最多差一手 ≈ 权益的 0.1–0.5%，且 `pending_restore` 不清零只是重复提交被拒的单），但会污染未成交结构报表。**下一轮修法**：宿主改按引擎同口径比较**整手对齐股数**（`target_sh = floor(target×equity/mark/100)×100` vs 持仓股数，`held ≥ target_sh` 即视为已达标），而不是比较权重。
8. **恢复次数口径**：本 run 的恢复计数只含 `reduced→normal`，不含 `insufficient_data→normal`——四条曲线的第一个宿主决策点 `previous_state=None`，机器按"HOLD 进入 normal"处理（不产出恢复行），D3 的 2 降档/1 恢复与此一致；合成测试 e2 里的"数据缺口恢复"行只出现在 provider 从 11:30 就被调用、且账户尚无任何已完成收盘的场景。
9. **run 目录的写入历史**：full 目录的产物与 manifest 全部来自最终一次通过（26 个 output 哈希逐一对齐）；`logs/runner.log` 是追加式日志，包含同目录内更早一次因一致性门失败而中止的尝试（该尝试未写 `outputs/`）。`runner.log` 与 `manifest.json` 不在 manifest 的 output 哈希表中（设计如此）。
10. **恢复腿的执行不对称（影响读者理解，不影响本轮判定）**：见 §4——降档腿 82–97% 当半日成交，恢复腿只有 17–44% 成交、只占买入名义 1.7–29.6%，敞口回升主要来自新席位入场。因此本轮不能宣称"完整的对称比例再平衡"；下一轮若要严格对称，需要给恢复腿与降档腿同等的执行力度（例如按 §1 的 `risk` 兜底，或允许补仓腿跨半日续挂直到补齐）。
