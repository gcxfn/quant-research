## 1. 项目目标与确定事项

为个人及少量独立用户提供一个 Windows 量化工作台：查看策略建议、同花顺行情、财联社新闻及私人 AI 研究。所有交易由用户自行执行，应用只记录实际成交，不连接券商下单。

### 1.1 已确认需求

| 项目 | 确定要求 |
|---|---|
| 交付 | 一个 Windows 便携 EXE，双击使用，不要求安装 Node、Python 或配置服务器地址 |
| 登录 | 用户名和密码；注册同样两个输入框；无邀请码、邮箱验证、独立昵称 |
| 视觉 | 黑白灰，参考 Codex 的克制与清晰；少按钮、少装饰，适合长期看盘 |
| 主界面 | 左侧策略、中间同花顺、右侧新闻 |
| AI | 私人 Pi 助手；默认收起，支持快速打开、拖动、缩放，不能挤没新闻 |
| 账户计算 | 所有金融计算在外部策略算法中完成；应用负责录入、存储、传输、展示 |
| 新闻 | 财联社电报为主要来源；统一采集、按天保存、共享简析 |
| 模型 | DeepSeek；供应商密钥仅在服务器私有配置中 |
| AI 用量 | 不设置每日消费、Token、调用轮数或总研究时间的人为额度；新闻分析限定100—200字 |
| 用户隔离 | 账户、会话、记忆、任务和文件按用户隔离；新闻及共享分析公共读取 |
| 运维 | HTTPS、公告、更新接口、备份、恢复验证、清楚的错误解释 |

### 1.2 方案约定与待核实事项

本文中的尺寸、接口路径、字段和目录是建议实现规格，可在开发时做小范围调整，但必须保留需求语义并同步文档。具体 SDK 方法、依赖版本和第三方接口参数，须在实施阶段依据对应官方资料及实际测试确认，不能照搬历史版本假定仍然有效。

需要核实：本地删除范围、服务器现有容器与数据卷、备份可读性、HTTPS证书状态、财联社接口可用性、DeepSeek实际可用模型、Pi会话恢复和同花顺登录兼容性。

### 1.3 第一版不做

- 券商连接、自动交易、代替用户下单。
- 自定义策略回测平台、因子研究管理平台、复杂插件市场。
- 手机端、多套主题、社交功能、交易排行榜。
- AI自动修改正式策略、账户账本、审核记录或共享新闻分析。
- 默认自动发起周期性研究。
- 大型权限后台、计费套餐、会员系统。

## 2. 重建前核查与恢复

### 2.1 核查顺序

1. 查看本地项目、Git仓库、可用构建产物和用户数据是否仍在。
2. 只读查看服务器相关容器、挂载卷、应用目录和备份清单。
3. 对可恢复数据制作独立副本；不要先初始化数据库或覆盖旧数据卷。
4. 在临时数据库中恢复最近一次完整备份，核对用户数、新闻数、会话数和附件清单。
5. 记录数据可恢复的最晚时间、缺失范围，以及恢复失败的明确原因。
6. 决定采用恢复后升级还是新建服务，不把部分恢复说成完整恢复。

历史线索包括服务器 `117.72.219.131`、应用目录 `/opt/quantdesk`、边缘代理目录 `/opt/quantdesk-edge`、备份目录 `/opt/quantdesk/backups`。这些仅用于定位，存在性及完整性必须重新确认。服务器上其他项目不得因为重建被停止或覆盖。

### 2.2 重建资料保护

- 新源码从第一天起提交Git，完成阶段性交付就打标签。
- 源码副本和数据库备份放在不同位置，避免一次误删同时损失两者。
- 密钥、数据库密码、SSH凭据不写入文档、源码、测试工件或EXE。
- 历史聊天出现过的真实密钥不得复制到新仓库；通过服务器私有配置重新接入。
- 若恢复旧账号，优先兼容原密码哈希及用户ID，不要求所有人重新注册。

## 3. 使用流程

### 3.1 首次启动

1. 用户双击EXE。
2. 显示简洁登录卡片，只有用户名、密码和登录按钮。
3. 点击小型“注册”入口切换表单，仍然只有用户名和密码。
4. 注册成功进入账户设置：现金、持仓、费率。
5. 账户保存后进入主界面；没有持仓可跳过持仓录入，不强制填虚假数据。
6. 策略未上线时显示“策略尚未接通”，新闻和AI仍可使用。

不显示服务器地址输入框、模型密钥输入框、容器设置或其他运维内容。

### 3.2 日常打开

自动恢复本人登录状态，加载上次查看日期、选中证券和界面尺寸偏好。认证失效回到登录界面，保留本机未提交草稿；退出后草稿不得显示给另一个用户。

### 3.3 每日常用动作

- 读左侧建议，点击证券联动中间行情。
- 点新闻标题查看原文摘要和共享AI简析。
- 点“追问”打开私人AI，并显示引用的新闻或策略对象。
- 实际交易完成后，在账户入口录入成交。
- 查看后台研究结果，下载报告或图表。

## 4. 视觉规范

### 4.1 整体原则

深色为第一版唯一主题。用字号、留白、细分隔线和灰阶组织信息；不使用彩色光晕、渐变背景、大面积装饰图、营销口号或不断闪动的元素。红绿仅允许用于明确需要区分的行情涨跌；错误优先用清楚文字和图标说明。

外观参考Codex的简洁感，但使用自己的Q标识，不复制其品牌素材。

### 4.2 建议设计变量

| 变量 | 建议值 | 用途 |
|---|---|---|
| 页面底色 | `#171717` | 工作台背景 |
| 面板底色 | `#1C1C1C` | 新闻、浮窗、弹层 |
| 悬停底色 | `#262626` | 可交互条目 |
| 输入框底色 | `#252525` | 表单及聊天输入 |
| 主文字 | `#ECECEC` | 标题与正文 |
| 次文字 | `#A3A3A3` | 来源、说明 |
| 弱文字 | `#858585` | 辅助时间信息；不能用来承载重要错误 |
| 分隔线 | `#333333` | 栏目分界 |
| 输入边框 | `#454545` | 输入及浮窗边框 |
| 主按钮 | 浅灰底、深色字 | 登录、保存、发送 |
| 圆角 | 输入8px，面板12px | 保持一致 |
| 间距 | 4/8/12/16/24px | 统一节奏 |

正文14px，辅助文字12px，标题16—20px。避免旧版出现的8—10px中文。金额使用等宽数字；证券代码、时间和版本号可用等宽字体。优先系统字体，如微软雅黑、Segoe UI，无需下载字体。

### 4.3 图标

- 主图标：深色圆角方块内白色几何Q。
- 保存可编辑SVG源及PNG预览，构建ICO包含16、20、24、32、40、48、64、128、256像素。
- 同时配置EXE资源图标、应用窗口图标、任务栏身份和便携启动器图标。
- 每次发布使用版本化文件名，减少同路径替换导致的图标缓存问题。
- 实际从交付EXE提取图标核验，再在资源管理器小图标、大图标和任务栏查看。
- 必要时通知Windows刷新图标，不能只修改图片文件就宣称EXE图标完成。

### 4.4 键盘与可访问性

Tab顺序符合视觉顺序，焦点边框清楚；按钮提供可读名称。Enter提交登录；聊天Enter发送、Shift+Enter换行，中文输入法组词期间Enter不能误发送。支持125%和150%系统缩放，禁止重要操作仅靠悬停才能发现。

## 5. 页面及布局规格

### 5.1 主窗口

建议初始1380×880，最小1120×700，并验证1366×768显示器。页面不出现整页横向滚动；各栏内容独立纵向滚动。

```text
┌──────────────────────────────────────────────────────────────┐
│ QuantDesk         公告／更新                 状态     账户入口 │
├───────────────┬──────────────────────────┬───────────────────┤
│ 组合建议      │ 证券名称／代码   浏览器打开 │ 市场新闻          │
│ 策略状态      ├──────────────────────────┤ 日期  全部／相关  │
│               │                          │                   │
│ 推荐证券      │ 同花顺官方页面           │ 电报标题          │
│ 仓位与价位    │ K线、行情、本人登录      │ 时间、来源、摘要  │
│ 建议数量      │                          │                   │
│               │                          │ 点开共享简析      │
├───────────────┴──────────────────────────┴───────────────────┤
│ 打开AI对话                         后台研究状态（有任务时显示）│
└──────────────────────────────────────────────────────────────┘
```

左栏建议宽260—300px；右栏300—360px；中栏占剩余宽度。顶部约52px，底部AI入口约40—44px。第一版不必加入三栏拖动分割，先确保AI浮窗可调大小。

### 5.2 顶栏

只保留品牌、轻量公告/更新、刷新状态、账户入口。正常状态不持续提示成功。公告可点开完整内容，不能只把正文藏在鼠标悬停提示里。账户菜单包括账户资料、录入成交、退出登录。

### 5.3 左侧策略栏

卡片展示证券名称和代码、建议目标仓位、买入区间、卖出区间、补仓区间、建议数量、费用后保本价及“解释建议”。字段没有返回时显示“暂无”，不显示0作为替代。

状态必须区分：策略未连接、审核未通过、暂不推荐任何股票、有效建议、行情过期、账户变化等待重算、计算失败。合法的零只推荐显示“当前建议空仓/暂不新增持仓”，不能当作系统故障。

卡片默认精简；策略版本、账户版本、行情时间、费用假设和审核依据放在详情。不能把研究信号标为可执行。

### 5.4 同花顺栏

顶部提供当前证券与一个代码输入框，另有“浏览器打开”按钮。用户自行在官方页面登录，同花顺密码和Cookie不得经过应用服务器。

内嵌页面异常时显示“同花顺页面暂时无法载入，可在浏览器打开”，应用其余模块继续工作。股票切换按经测试的官方URL规则转换；不根据未经核实的字符串拼接假装已经切换成功。

### 5.5 新闻栏和详情

列表按发布时间倒序，支持北京时间日期选择和全部/相关切换。每项显示时间、来源、标题与一小段摘要。不在每条新闻上堆放多个操作按钮。

详情包括原始内容、AI简析、来源链接、发布时间、更正状态和“向AI追问”。正文长时详情内部滚动。首次分析显示“正在生成，共享结果完成后会自动保存”；失败显示重试，不把错误当成正文。

### 5.6 AI快速对话窗口

首选独立Electron BrowserWindow，使用同一应用的私人会话服务：

- 默认不弹出；底部入口或新闻追问打开。
- 初始约560×440，最小380×300，操作系统负责拖动、缩放。
- 默认不置顶，打开时获得焦点；不要长期遮住其他应用。
- 标题栏简洁，保留移动区域、会话入口、收起/关闭。
- 消息区占剩余空间，输入框初始约44—56px，随多行内容增加到最多120px后内部滚动。
- 关闭浮窗只隐藏窗口或销毁本机视图，不取消服务器任务。
- 用户主动点“取消”才取消研究。
- 记录窗口尺寸和位置，恢复时限制在当前可见屏幕范围，防止拔掉副屏后找不到窗口。
- 最大化浮窗即可作为完整研究页，不另建复杂工作区。
- 会话、任务、文件和记忆集中在可收起侧栏，默认隐藏。

独立窗口的目的，是避免原先网页浮层与同花顺原生WebContentsView相互遮挡。若阶段性交付先用应用内浮窗，必须明确它的兼容限制，不能宣称已做到行情与聊天同时可操作。

### 5.7 表单和初始设置

现金与持仓成本使用十进制输入，费率明确单位，如“佣金：万分之几”或“基点”，必须统一显示与传输转换。账户表单可按现金/持仓/费用三段排列，不做多层配置向导。保存时保留原输入；失败不能清空。

成交输入：证券、方向、实际数量、实际价格、实际时间、实际费用（已知时）。未知实际费用与算法估算费用必须区分。待对账成交显示独立状态，不立即篡改账户数值。

## 7. 桌面安全与多窗口协作

### 7.1 主进程与界面职责

主进程持有认证凭据、调用固定服务器、管理文件对话框和同花顺会话。React只拿界面需要的数据，通过有限IPC方法操作，不能调用任意URL、Shell或本机路径。

设置 `contextIsolation=true`、`nodeIntegration=false`，渲染进程开启沙箱。校验IPC发送者是否属于应用自己创建的可信页面。同花顺页面不暴露应用登录IPC。

### 7.2 多窗口身份一致性

- 每次登录建立本机认证代次标识，主窗与AI窗共用主进程保存的当前身份。
- 退出、切换用户、令牌失效时广播清理事件，关闭旧SSE，清空旧消息并销毁旧AI窗口。
- 旧窗口发来的请求即使迟到，也必须拒绝或与旧代次隔离。
- AI窗URL不携带Token、用户名密码或账户数据；引用对象通过受控IPC传入。
- 同一用户多个窗口打开同一任务，共享任务状态，不因此新建研究。

### 7.3 本机数据

认证令牌使用Windows提供的安全存储能力，避免明文写入普通JSON。窗口大小、新闻筛选、未发送草稿按应用用户隔离。日志不记录密码、Cookie和模型密钥。

同花顺使用按应用用户ID划分的持久化分区。普通关闭应用保留登录；显式“清除同花顺登录”才清理对应分区。不强制清空所有用户浏览器数据。

### 7.4 外链与下载

外链仅允许经过校验的HTTPS地址，禁止自定义协议和本地文件协议。下载研究文件时根据服务器返回的安全文件名打开保存对话框，不自动运行文件。下载请求必须带本人认证，重定向不得携带凭据去未知域名。

## 8. 认证与用户管理

### 8.1 用户名

建议允许2—32位中文、字母、数字、下划线、点和短横线。服务端统一去首尾空白并对拉丁字母大小写归一；注册唯一约束使用同一规则。显示名默认取用户注册的用户名原始大小写，不再要求额外输入。

恢复旧系统时，可保留邮箱形式的登录名兼容，不把旧账户映射到新随机身份。不要使用“用户名拼成假邮箱”的隐式转换。

### 8.2 密码和会话

密码最少8位，使用适合密码的哈希算法及随机盐。会话可撤销，数据库存令牌哈希而非原始Token。密码错误、用户名不存在统一提示“用户名或密码不正确”。注册冲突说明用户名已使用。

登录和注册保留合理的反滥用请求限速，与AI消费额度不是一回事。代理后的真实IP只信任已配置边缘代理，不能信任客户端随意提交的转发头。

## 9. 账户、成交与策略接口

### 9.1 单一计算来源

应用只校验数据格式、权限、版本和重复请求。T+1、可卖数量、最低佣金、保本价、共享现金、建议数量等金融规则由策略服务决定；应用不再实现一套近似算法。

账户成本究竟是摊薄成本、实际买入均价还是包含费用的账面成本，必须由策略合同明确，界面使用相同名称。不能在展示层自行换口径。

### 9.2 账户快照

建议字段：

- `account_id`、`account_version`、`as_of`、`currency=CNY`。
- `cash_available`、`holdings[]`、`fee_schedule`、`slippage_assumptions`。
- `allowed_boards[]`、`open_t[]`、`pending_trade_ids[]`。
- 持仓包含证券、资产类型、数量、成本口径、成本金额、当日可卖数量、可卖数量对应交易日。
- 费率股票/ETF分别保存，包含最低佣金和必要税费假设。
- 未知数据用null并附原因；零现金是合法数值，不等于缺失。

金额、价格和费率跨语言传输使用十进制字符串，计算端使用Decimal或等价十进制方式；时间使用带时区的ISO8601。证券统一内部代码规则，例如 `SH600000`，显示层可转换大小写。

  "operation": "recommendations",
  "request_id": "uuid",
  "idempotency_key": "uuid",
  "account": {
    "account_id": "uuid",
    "account_version": 12,
    "as_of": "2026-09-17T09:35:00+08:00",
    "currency": "CNY",

      "stock": {"commission_bps": "2.5", "minimum_commission": "5.00"},

### 9.4 返回结果

返回包括 `status`、`executable`、`reason_codes`、`account_version`、`strategy_version`、`review_status`、`market_as_of`、`valid_until`、`assumptions`、`items`。

`items=[]`可以是正常空仓建议。每个标的包含权重、买卖/补仓区间、建议数量、费用后保本价、依据及限制。价格区间采用明确的lower/upper字段，不把“1410—1436”字符串当成唯一机器可读数据。

算法结果与审核元数据都要校验；仅有返回字段 `executable=true` 不足以绕过发布门禁。

### 9.5 并发、失效与成交对账

1. 用户保存账户时带 `expected_version`，不匹配返回版本冲突，避免静默覆盖。
2. 同一事务保存账户、递增版本、使旧建议失效，并写入可靠后台任务记录。
3. 建议计算开始时绑定快照版本；结束时若当前账户已变，旧结果只留审计，不成为当前建议。
4. 成交先作为不可变事实记录保存，带唯一幂等编号和内容摘要。
5. 同一幂等编号、相同内容重试返回原结果；相同编号、不同内容返回冲突。
6. 算法对账结果携带原账户版本和已应用成交ID，通过事务及唯一约束避免重复入账。
7. 手动修正成交通过更正记录关联原成交，不能无痕覆盖历史。
8. 网络中断、算法异常、版本冲突时保留待对账记录并提示，不自行计算一份账户余额。

### 9.6 刷新与行情

默认5分钟，支持1分钟；交易时间以市场日历和北京时间判断，不能只用周一到周五近似。账户变化立即触发重算。策略选股周期由算法决定，不能每次行情刷新都换名单。

策略计算用独立行情接口，同花顺只供看盘。每条行情附来源、采集时间和交易时间；数据有效阈值由策略合同定义。收盘后日线快照与交易时段实时快照使用不同有效性规则。

## 10. 新闻与共享分析

### 10.1 采集

服务器集中拉取财联社电报，客户端只访问业务服务。采集周期配置化，建议先以60秒量级低频验证，再根据来源限制调整；支持超时、退避、断点游标及重复去除。不做高频无节制请求。

来源配置记录接口版本、允许用途的实际依据、内容存储范围、采集状态和覆盖说明。用户已确认自用判断，不将这一点伪写成获得了官方书面授权。

### 10.2 按天存储

数据库是检索和去重主存储，日归档便于备份和恢复。建议布局：

```text
news-archive/
  cls/2026/09/17/items.jsonl
  cls/2026/09/17/manifest.json
  cls/2026/09/18/items.jsonl
```

日期按新闻发布时间转换到Asia/Shanghai；同时保存采集时间。跨天补采或更正写入对应新闻日期的归档版本/修订记录。每条包含来源ID、正文、发布时间、采集时间、原文URL、内容版本和内容摘要值。

数据库成功、归档失败时记录待归档工作，后台重试；通过归档清单和唯一ID对账，避免两个存储悄悄不一致。归档不能成为新闻列表每次查询必须全盘扫描的依赖。

### 10.3 更正与去重

来源+来源文章ID为主去重键；缺少可靠ID时使用明确的替代策略并记录。标题相同不等于同一条新闻。正文更正增加内容版本，旧分析标为过期；不把旧分析覆盖成看似针对新正文。

### 10.4 共享AI分析

缓存与任务合并键：`news_id + content_version + provider/model + prompt_version + output_schema_version`。数据库唯一约束保证多人同时点击只产生一个逻辑任务。

状态：待生成、排队、生成中、完成、失败、已过期。任务持有租约/心跳，服务异常退出后可以识别失联任务。重新生成不得同时启动多份。

输出100—200字，建议短段落形式：事实、影响方向和路径、不确定性。统一定义字数：正文去除空白后的Unicode字符数，原文链接与来源标签不计入。服务端校验长度，超长可做一次精简重写；仍不满足时提示生成失败，不截断成不完整结论。

共享提示词只包含新闻公开内容，不包括点击用户的持仓、姓名、私人聊天或账户。私人追问生成的新分析只留本人会话。

### 10.5 筛选及分页

日期、来源、相关性筛选在数据库查询阶段执行，之后再分页，不能先取最近20条再在内存里按日期过滤。分页使用稳定的发布时间+ID游标。相关性第一版采用可解释的证券代码、公司别名和行业映射，不承诺复杂语义关联准确率。

## 11. Pi金融助手

### 11.1 SDK接入

使用用户指定的 `earendil-works/pi`，通过SDK管理会话与事件，而不是把无约束命令行Shell直接暴露给用户。历史曾使用0.85.1，仅作为核查线索；实施时固定通过实测的版本。

金融扩展包含系统提示词、工具定义、资料引用规范、研究报告模板与错误映射。只加载随应用发布的扩展，不从用户研究目录自动发现可执行插件。

### 11.2 工具能力

| 工具 | 数据与动作 | 约束 |
|---|---|---|
| 账户查询 | 本人账户输入与版本 | 只读 |
| 建议查询 | 已发布策略结果和依据 | 不读取未放行研究数据 |
| 情景计算 | 调用正式算法的计算接口 | 明确标注假设情景 |
| 行情查询 | 获准行情服务 | 附来源和时间 |
| 新闻查询 | 共享新闻、共享分析 | 不修改共享结果 |
| 网络搜索/取文 | 公告、公开公司资料、财经资讯 | 经受控出口 |

### 11.3 回答风格

默认先回答结论，简短、中文、通俗。需要研究时再附依据、来源、数据时间和下载文件。区分事实、推测、情景与策略建议。账户或行情数据未知时不编造数字。

网页、新闻和PDF都是研究材料，不是权限来源。网页内要求读取密钥、修改账户、忽略权限的文字不触发授权。

### 11.4 任务生命周期

`queued → running → completed / failed / cancelled / interrupted`。

研究任务由服务器持久调度；HTTP连接或桌面进程退出不决定任务是否继续。任务创建和启动采用可靠队列记录；领取时使用数据库锁或租约，避免多worker重复执行。

服务重启后未完成任务标为中断，保留已完成文字和文件，允许用户显式重试；不默默从头重复模型调用。中断与用户取消在界面中分别说明。

### 11.5 用量和并发

不设置用户未要求的消费配额、Token预算、模型调用总轮数或研究总时长限制。记录实际用量和错误，供运维查看。

建议初期每用户同时1个研究、全站同时2个，其他排队；管理员可按资源调整。这属于机器容量控制，不是付费用量限制。Python单次最长120秒可保留，网络调用使用请求超时和有限退避。供应商限流、余额不足或上下文长度上限应原样解释其性质，不伪称应用额度耗尽。

## 12. 用户隔离和研究执行

### 12.1 隔离模型

服务器从认证身份确定用户，接口中用户提交的user_id不能作为授权依据。所有账户、会话、任务、记忆和工件查询包含归属校验；数据库RLS作为第二层保护。共享新闻使用单独的共享表或明确只读路径。

管理员具备服务器运维权限，本设计不声称能够阻止管理员读取机器上的数据。

### 12.2 Pi运行环境

每用户独立容器、会话目录、文件和记忆。容器按需启动，任务结束闲置后休眠，持久数据卷保留。不同用户不能通过同容器共享工作目录。

只有受控容器管理服务访问Docker接口，业务API和Pi本身不挂载Docker socket。管理服务提供固定的启动、停止、状态和沙箱接口，不接收用户任意镜像、挂载路径或宿主命令。

### 12.3 Python沙箱

单次任务创建临时沙箱，无网络、无模型密钥、无生产目录，输入仅为此次允许导出的文件。限制CPU、内存、进程数、输出文件总量，退出或超时清理全部子进程。

输出回收检查真实路径、软链接、文件类型和大小，不把沙箱中的链接当成可下载宿主文件。仅将合格输出登记为本人研究工件。报告与原始执行日志区分保存。

### 12.4 联网与模型网关

联网出口拒绝回环、私网、链路本地、云元数据和其他用户服务；每次重定向重新检查，考虑DNS解析后地址变化，不能只检查输入URL字符串。

真实DeepSeek密钥只在模型网关。Pi持有受限身份，由网关关联用户和任务；接口不允许客户端指定任意上游模型地址。返回错误时过滤凭据和个人内容，日志只记必要元数据。

### 14.1 消息请求示例

```json
{
  "idempotency_key": "uuid",
  "content": "这条新闻可能影响哪些行业？",
  "references": [{"kind": "news", "id": "uuid", "version": 2}],
  "mode": "research"
}
```

返回HTTP202和task_id。提交超时后使用同一幂等键查询/重试，不能每点击一次就换新键。用户改变正文或引用后才视为新请求。

### 14.2 SSE事件

事件具有单任务单调递增编号，数据库先持久化再推送。类型建议包括 `task_started`、`text_delta`、`tool_started`、`tool_finished`、`artifact_created`、`task_completed`、`task_failed`、`task_cancelled`。

重连发送Last-Event-ID，只补之后事件。历史完整消息与流式增量必须按task_id/message_id去重，不能先加载半段答案又从事件0重放一次。事件已过保留期时返回明确的“需重新读取任务快照”，不能偷偷丢失中间状态。

### 14.3 错误响应

```json
{
  "error": {
    "code": "MODEL_BALANCE_INSUFFICIENT",
    "message": "模型服务余额不足，请联系管理员处理。",
    "retryable": false,
    "request_id": "uuid"
  }
}
```

使用清晰错误码区分认证、参数、版本、网络、上游和内部异常。响应不附堆栈、密钥、原始密码或未脱敏上游请求。

## 15. 网络异常与反馈文案

| 情况 | 用户看到的说明 | 行为 |
|---|---|---|
| 离线 | 当前网络不可用，已保存内容仍可查看 | 保留页面与草稿，恢复后重试 |
| 服务器超时 | 服务器响应较慢，请稍后重试 | 同幂等键重试写请求 |
| 登录过期 | 登录已过期，请重新登录 | 清理旧窗口认证与流 |
| 策略未接通 | 策略算法尚未接通，账户资料可以先保存 | 不生成替代建议 |
| 策略未审核 | 当前策略仍在研究中，暂不提供可执行建议 | 可查看明确标注的状态 |
| 行情过期 | 行情已过期，建议暂不可执行 | 保留旧值及时间并禁用可执行标识 |
| 财联社异常 | 财联社暂时无法更新，正在显示已保存新闻 | 展示最后成功时间 |
| AI余额不足 | 模型服务余额不足，管理员处理后可继续 | 不无限重试，不影响新闻正文 |
| AI供应商限流 | 模型服务繁忙，正在等待重试 | 有限退避，用户可取消 |
| 流连接断开 | 回答连接中断，任务可能仍在继续 | 重连读取事件，不创建新任务 |
| 后台服务重启 | 上次研究因服务重启中断，已保存内容仍可查看 | 显式重试 |
| 同花顺加载失败 | 同花顺页面暂时无法载入，可在浏览器打开 | 保持其他模块可用 |
| 文件失效 | 文件暂时无法读取，请稍后重试或重新生成 | 不下载空文件假装成功 |

正常操作不弹一串成功提示。错误优先放在所属模块，只有登录失效等全局问题才覆盖工作区。

## 16. 部署与配置

### 16.1 服务组成

边缘HTTPS代理、业务API、后台worker、PostgreSQL、模型网关、联网代理、容器管理服务、按需Pi容器和临时Python沙箱。初期允许部分后台职责合并为一个worker，保持明确代码边界即可，不为少量用户搭建复杂集群。

数据库、Docker管理接口、模型网关不直接暴露公网。公网只开放必要HTTPS入口；SSH作为运维入口独立管理。

### 16.2 配置项

公开配置：应用服务地址、版本、新闻刷新周期、交易时间刷新周期。服务器私有配置：数据库密码、会话签名/能力令牌密钥、模型API地址和真实密钥、模型名、新闻来源配置、备份目的地。

资源配置：全局/每用户并发、容器内存CPU、Python执行超时、单文件和工件总量。不要把无上限需求误实现为默认10分钟研究结束或20次模型调用结束。

优先使用域名。若继续用IP HTTPS，证书必须真实支持该IP且客户端正常信任；续期、证书重载和临近过期提示都要实测，禁止靠忽略TLS错误上线。

### 16.3 模型兼容性验证

验证模型列表、普通请求、流式请求、工具调用、取消和错误映射。通过自建网关时，上游域名自动识别可能失效，因此请求字段和角色兼容性要显式测试，包括developer/system角色、token字段和思考模式选项。只根据实际兼容情况配置，不复制不必要字段。

### 16.4 备份与恢复

- 每天备份数据库、新闻归档、Pi会话文件、研究工件和必要运行配置。
- 配置中的密钥如需备份，单独加密、限制访问，不与公开源码混放。
- 备份先写临时目录，完成校验后再标记完整；部分失败不得进入“最近成功备份”。
- 数据库使用一致性导出；文件采用快照或短暂协调写入，记录开始/结束时间。
- 至少留一份异机或离线副本。保留周期初期建议7份日备份+4份周备份，按容量调整。
- 定期在临时环境恢复并检查数据、用户归属和工件可读性；成功后删除临时环境。
- 初期恢复目标：最多损失一天新增数据；恢复耗时目标在第一次演练后按实测记录，不凭空保证。

### 16.5 日志与状态

日志包含request_id、任务ID、模块、耗时和错误码，不默认记录聊天全文。模型用量、新闻最后成功采集时间、队列长度、磁盘空间、证书状态、备份结果作为运维指标。客户端状态页不显示内部网络、密钥路径或容器细节。

## 17. 单EXE打包、版本与更新

### 17.1 便携版的准确含义

用户只拿一个EXE即可运行。Electron便携运行时仍可能自动解包到临时目录，并在用户目录保存设置和浏览器会话；这不要求用户手动安装或管理文件，不能承诺运行时绝不产生任何目录。

第一版发布Windows x64。构建锁定依赖，打包仅包含运行文件与图标，不带.env、源码密钥、测试账户、服务器私有目录。

### 17.2 发布流程

1. 增加语义版本号，更新发布说明。
2. 跑本次变更相关测试和桌面构建检查。
3. 生成 `QuantDesk-Portable-x.y.z.exe`。
4. 从EXE资源提取图标检查，执行实际启动测试。
5. 对产物生成SHA256，上传只读下载位置。
6. 发布包含版本、下载URL、校验值、兼容范围和公告的元数据。
7. 用上一版客户端测试发现更新与下载；旧版本仍能正常使用兼容接口。

### 17.3 MVP更新交互

第一版采用“发现新版本 → 查看说明 → 下载新版 → 用户关闭旧版并启动新版”的简单流程。下载校验通过后才提示可用；失败保留原EXE。用户配置放在稳定目录，不能随着便携EXE临时解包目录变化而丢失登录。

不把便携包当成普通安装版直接套用未验证的自动覆盖更新。后台静默替换正在运行的EXE后置，若未来需要，单独实现可信更新辅助进程与回滚机制。

如具备代码签名证书则签名；没有时如实说明系统可能显示未知发布者，不能把构建日志里的“signing”一行当成可信数字签名完成证据。

## 18. 实施阶段与交付门槛

### 阶段0：恢复核查和接口冻结

产物：恢复报告、有效需求清单、页面草图、账户/策略接口合同、依赖版本记录。

完成条件：确认哪些数据存在；至少证明服务器访问、模型基础调用、财联社采集和Pi最小会话可以工作，或明确列出阻塞项。

### 阶段1：可启动桌面与账户

实现用户名注册登录、账户录入、三栏黑白界面、Q图标、独立AI空窗口。用明确标记的合成数据做布局验证，演示与真实模式不能混淆。

交付：可双击的EXE；无需邀请码和邮箱；能保存本人账户；退出换用户不会看到前一人的信息。

### 阶段2：真实新闻和共享分析

实现财联社采集、每日持久化、新闻筛选分页、详情、共享分析合并与失败重试。

交付：两位用户打开同一新闻只创建一个逻辑分析任务；私有账户不进入共享提示词；跨天查询和更正行为正确。

### 阶段3：私人Pi与后台任务

实现SDK接入、私人会话、多窗口事件同步、SSE重连、取消、历史恢复、记忆及工件下载。

交付：真实模型对话通过；关闭EXE任务继续；重新打开能读取结果；两个用户的聊天互不可见。

### 阶段4：联网和Python研究

实现受控联网、公告获取、沙箱、研究报告与图表。完整研究不设置人为总时长/轮数配额。

交付：能用授权数据完成小型研究；沙箱不能读宿主机、其他用户文件或模型密钥；取消和超时能清理子进程。

### 阶段5：策略接线

接入正式算法的建议、情景计算、成交对账。若算法尚未交付，先完成合同测试和不生成假建议的等待状态，这部分不能假称正式策略已上线。

交付：账户变化旧建议失效；费率和持仓输入完整传递；算法结果与界面一致；通过正式审核后才开放可执行标识。

### 阶段6：整体试用和发布

测试真实EXE、Windows缩放、同花顺登录、断网与余额错误、备份恢复、公告和更新。修完阻断日常使用的问题，再发布版本化EXE及完整交付材料。

## 19. 并行协作安排

尽量使用子代理处理独立模块，主对话负责统一合同和集成，不让多个代理同时改同一文件。

| 工作 | 负责人范围 | 独立输出 |
|---|---|---|
| 桌面 | 页面、浮窗、图标、打包 | 桌面代码、交互验证 |
| 业务服务 | 认证、账户事实、新闻、任务状态 | API和数据库迁移 |
| Pi与基础设施 | SDK、工具、容器、沙箱、网关 | 独立运行环境和工具测试 |
| 验收 | 跨用户、幂等、断线、恢复、真实EXE | 可复现验收记录 |
| 集成 | 主对话 | 接口裁决、部署、最终产物检查 |

先冻结共同接口再并行。子代理的“完成”只代表提交可审查成果；主对话检查实际产物后才能对用户宣布已完成。模型不可用或受限时直接改为可用执行方式，不空等。

## 22. 重建时的取舍原则

先把用户真正每天会用的路径做好：打开、登录、看行情、看新闻、问AI、保存账户和录入成交。对用户隐藏部署细节，对开发保留清楚的合同与版本。实现以简单可靠为准，不为了预想的大规模产品堆复杂系统。

正式策略未完成时，应用可以先交付新闻、行情、账户录入和私人研究，但必须明确显示策略等待状态。所有策略金融计算坚持单一算法来源，避免前端、后端和AI各算一套。

## 附录A：实施时必须补齐的操作细节

### A.1 单实例与数据目录

同一Windows用户默认只运行一个QuantDesk主实例。再次双击EXE激活已有主窗口，不再创建另一套本机状态或重复连接任务。AI浮窗由该主实例管理，不是第二个独立登录客户端。不同Windows用户的数据按系统用户目录自然隔离。

本机使用稳定的应用数据目录，不依赖EXE所在文件夹或临时解包目录；应用更新不能意外切换用户数据目录。配置文件有版本号，升级先备份再迁移；失败时保留原文件并给出可理解的错误。

### A.2 快照来源与费率生效时间

账户快照补充 `snapshot_id`、`input_source`、`content_digest`，用于审计和重试识别。费用设置记录版本和生效时间；历史成交应使用其适用的真实费用事实或对应算法假设，不能直接拿今天修改后的费率重算历史账本而不留记录。

验收可以使用独立核对脚本比较“用户输入→业务保存→策略收到”的字段和值，发现缺失、单位转换或精度损失即不通过。这是验证数据传输，不是在应用内另建金融计算引擎。

### A.3 人工成交的范围

第一版记录已经发生的成交，不建立券商订单状态机，也不新增下单、撤单、废单接口。多次分批成交可分别录入，每笔拥有独立幂等编号；需要关联时增加用户可选的分组标识。合并、撤销录入或修正都要留审计记录，不能抹掉已对账历史。

### A.4 SSE心跳与可复现断线测试

事件流建议每15—30秒发送无业务编号的心跳注释，代理配置允许流式响应且不缓存事件。业务事件才消耗序号；客户端仍按task_id和event_seq去重。

测试步骤：发起长回答，接收部分事件后断开网络30秒，再恢复；核对同一task_id、同一消息最终内容和持久事件序列，确认没有再次提交研究、没有重复字符、没有漏掉完成状态。

### A.5 新闻停机缺口

采集器记录每次成功区间和最后游标。停机后优先按来源实际支持的方式回补；接口只返回最新少量电报而无法补齐时，标记缺口开始/结束时间及原因。测试不能简单要求“重启前后新闻总数相同”，因为期间可能有新新闻；应检查重叠区间无重复、原记录未丢失、新记录正确增加且缺口可见。

### A.6 更新和任务相互独立

桌面更新只影响本机界面，不需要等待服务器上的研究完成。关闭旧版前保存本机草稿与事件游标，研究继续在服务器运行，新版通过同一认证身份恢复查看。第一版仍采用下载新版并手动启动，不加入未经验证的运行中覆盖、改名和自动回滚逻辑。

更新检查使用短超时，服务器离线也不能阻塞应用启动。SHA256用于检查文件完整性；下载来源身份依赖可信HTTPS及发布控制，不能把同一不可信来源给出的校验值当成独立安全证明。
