## 1. C1：滚动训练窗口方向错误 —— 确认，已修复

**证据**（两个归档训练脚本同一构造）：
- `artifacts/runs/20260921T125117-alpha158-90aa2/tmp/runner_alpha158.py:220-223`
- `artifacts/runs/20260921T142710-a158-head-b41d/tmp/runner_head_ml.py:216-219`

```python
train_ts = [u for u in ordered[:i] if u < t][:24]  # y known <= t-1
train_ts = [u for u in train_ts if ordered.index(u) < i]
```

`ordered` 为升序月份序列，`ordered[:i]` 再 `[:24]` 取的是**最早**
24 段：预测 2016 年时训练用 2015 年起 24 个月，预测 2020 年时
**仍然**用同一段 2015-2016 数据。两个过滤条件均为恒真冗余，不
起修正作用。归档运行的全部 LightGBM 模型从未见过 2017 年以后
的训练数据。

**修复**（`src/quant/research/alpha158_ml.py`）：
- `select_train_sections()`：先按"标签完整可得"过滤（截面 u 的
  标签结束日 ≤ 决策日 t，决策在 t 收盘后，标签恰在 t 结束的算
  可得），再取**最近** `max_train_sections` 段；
- 每个预测月输出诊断：`train_start / train_end /
  label_end_latest / n_train_sections / n_train_samples /
  n_predict`（落盘 `train_window_diag_*.csv`）。

**新增测试**（`tests/unit/test_alpha158_ml.py`，真实运行通过）：
- 40 个月人工时间轴：预测时点推进后训练窗口必须推进，且饱和
  24 段后窗口起点也推进（旧缺陷表现为起点冻结）；
- 任何训练截面的标签可得时点不晚于决策时点（对全部截面×决策
  点断言）；
- 最近 24 段恰为 `ordered[-25:-1]`。

**影响边界**：归档 IC、头部命中率、ml_scores.json 及其全部下游
回放（见 `affected_runs.csv`）的训练层都基于冻结窗口，污染方向
（早期窗口偏离近期分布）已确认，幅度待基线重跑量化。

## 2. C2：预测股票名单依赖未来池资格 —— 确认，已修复

**证据**（两个训练脚本同一构造链）：
1. 特征只为当期池计算：`for sym in pools_at[t]["ranked"]`
   （S1 L91 / S2 L87），`FEATURES[t]` 键 ⊆ t 月池；
2. 标签字典：`FWD[t] = {sym: CLOSE_AT[t1][sym]/px-1 ... if sym in
   CLOSE_AT[t1]}`（S1 L120-124 / S2 L116-120），而
   `CLOSE_AT[t1]` 的键 ⊆ `FEATURES[t1]` ⊆ **t+1 月池**；
3. 预测矩阵：`syms = sorted(FWD[t])`（S1 L189 / S2 L183）。

三步串联后：**t 月的预测名单排除了 t+1 月失去池资格（或 t+1
月无自身成交）的股票**——用下月才知道的资格状态筛当月候选。
step-1 的 158 因子 IC 评估截面、52.5% 命中率的中位数基准截面同
样受污染（困难样本被系统性剔除，方向偏乐观）。

**修复**（`alpha158_ml.py build_ml_sections`）：
- 当期预测全集 = `FEATURES[t]` 全部键，逐月断言与 t 时点特征
  键一致（runner 内 `assert` 强制）；
- 标签独立构造，清算口径：下一信号日**及以后**第一个自身成交
  收盘计标签（长期停牌/退市股按恢复后首笔收盘清算），无成交则
  保留在预测全集、标签缺失并披露计数——不再从截面删除困难样本；
- 训练样本 = 标签完整可得的截面（与 C1 修复同一过滤器）。

**新增测试**（真实运行通过）：
- 不变性：只修改 t 之后的池资格与价格，t 时点预测名单与分数
  逐位不变（LightGBM 固定种子，两次完整流水线对比）；
- 退出未来池的股票仍留在 t 时点预测全集；
- 停牌股保留于全集、标签缺失计数披露、后续决策点训练不受缺失
  标签影响。

## 5. Q1：分批止盈状态与实际成交的一致性 —— 确认缺陷，已修复并端到端核验

**证据**（旧 `single_name_rules.py:120-123`）：`half_taken` 在
**决策发单时**置位，且一旦置位永不再发半仓卖单——无论订单是否
成交、是否被替代。

**引擎侧核对结论**（回答任务书"引擎是否持续维护风险订单"）：
是——risk intent 生成订单后不置 done（`band_engine.py:3607`
仅非 risk 半日失效），每个决策点重锚重发，连续 3 个半日未成交
武装开盘兜底（`bump_streak`，L3108-3117）；成交即 `risk_state.pop`
重置。因此"未成交"场景由引擎兜住，**漏卖窗口在被 override 或
无行情时出现**：同一决策点同一标的只允许一行（inject 去重），
新 intent（如 overlay 减仓）会 override 旧 halving 单，此后若
`half_taken` 已置位，规则不再重发——半仓卖出意图丢失，直到
跌破保护线或到达 +3R 才恢复退出。

**修复**（`single_name_rules.py`）：
- 状态拆分：`half_armed`（+2R 已触发）与 `half_done`（账本
  clip 份额实际到达减半目标，判定 `shares <= keep_target+LOT-1`
  向重发方向保守）；
- `armed && !done` 期间**每个决策点重发**减半目标（保留名义形
  式），幂等性由引擎保证（`at_target_skips`：已在目标上不发单；
  新行 override 旧行不叠加）；成交落地即 done，停止重发；
- `clip_diagnostics()` 暴露 armed/done/shares0 供 runner 与测试
  对账。

**新增测试**（全部真实运行通过）：
- 单元 9 项：未成交重发、部分成交（中间持仓）继续重发同一目标、
  到达目标即 done、armed 穿越回调持续、整手边界；
- 端到端 2 项（`tests/test_single_name_rules_e2e.py`，band 引擎
  全链路）：① 触发→两个半日未穿透（streak 计 2）→穿透成交
  5000 股→done 停发；② 外部 profit 单 override→中间持仓
  8000→下一决策点从账本恢复重发→精确落到 5000 目标，无重复
  卖出。T+1 语义由既有 `test_band_dynamic.py` d3 覆盖，此处不
  重复。

**行为变更披露**：旧测试断言"latch 后同价格不再发单"——该行
为正是缺陷本身，已按新语义更新断言（见
`tests/test_single_name_rules.py` t1 注释）。

### 5.1 复核追加（2026-09-21 晚）：首轮 Q1 修复的两处回归与再修复

独立复核（4 个只读子代理 + 引擎对照实验）确认首轮修复引入两个
比原缺陷更严重的新缺陷，本节如实记录：

- **回归 A（多批次重复卖出）**：首轮语义"每决策点重发按批次
  计算的保留量之和"，而引擎卖单按整仓目标成交、FIFO 消耗旧
  批次——首笔成交扣掉未触发批次后，重算的保留量再次下降，同一
  减半意图被重复执行。复核实验：3,700 股旧批次 + 4,700 股新
  批次（仅后者到 +2R），应卖 2,400 股，首轮修复累计卖出 6,100
  股、把止损保护尚在的旧批次全部卖光。首轮基线回放（192112）
  中 216 个买入标的中 76 个存在多批次持仓，其净值与"个股退出
  −0.46pp"归因被污染，该运行作废（见基线报告无效版本清单）。
- **回归 B（K=3 兜底失效）**：重发行的 `source_signal` 用当日
  日期，引擎按 (symbol, intent, source) 维护连续未成交计数，
  source 每日变化导致计数每日清零，连续三个半日的开盘兜底永远
  不武装，违反 AGENTS §1 风险减仓兜底要求。

**再修复**（`single_name_rules.py` 重构，核心思路：减半从"按
批次的目标"改为"整仓冻结绝对目标事件"）：
- 触发时刻冻结 `target_shares`（当期各批次保留量之和的绝对值）
  与 `source`（触发日）；事件存活期间每决策点重发**同一个绝对
  目标**且共用**同一个 source**（streak 保持、K=3 正常武装）；
- 事件完成 = 账本持仓 ≤ 目标（一手容差）；完成后参与批次标记
  `half_done` 永不再减半——FIFO 无论消耗哪个批次，绝对目标都
  不变，重复卖出在结构上不可能；
- 一次只允许一个活跃事件；+3R 全清等活跃事件结束后于下一决策
  点成新事件（保守方向）。

**验证**：新增测试 5 项全部真实运行通过——单元层多批次不超卖
（审核场景手算复现：恰卖 2,400、落在 6,000）、事件源冻结、多
批次第二批后触发；端到端层多批次 FIFO 链（`e3`：期末持仓恰
6,000={1,300 旧+4,700 新}，无后续卖单）与 K=3 兜底链（`e4`：
三个半日未穿透 → streak 1→2→3 → 武装 → 次半日开盘市价兜底成
交 5,000 股）。全仓 **680 passed**；NOSNR-bin（不调用退出模块）
与被否决版本逐位一致，交叉证明基础设施未变。基线以
`20260921T194738-baseline-replay3-c5d8h2` 重跑，见基线报告。

### 5.2 二轮复核追加（2026-09-21 夜）：v3 残留三缺陷与修复

第二轮独立复核（复跑全量测试 + 3 个子代理真实引擎实验）确认
v3 修复成立，但暴露三个残留缺陷（前两个为旧代码既有行为，非
v3 引入；v3 的问题是没有披露且文档过度声明了修复）：

- **残留 A（止损/保护线 K=3 失效）**：整仓退出行 `source=day`
  逐日变化，引擎 M1 规则把 source 变化当作新信号、连续未成交
  计数每日清零——v3 模块文档声称"K=3 兜底仍然武装"只对减半腿
  成立。复核实验：连续 6 个决策点计数序列 1,1,2,1,2,1 永不
  达 3；真实回放 5 条曲线无任何止损/保护线标的武装过；另有
  案例是席位退出兜底已武装、同时点止损行把武装状态清掉。
  违反 AGENTS §1"风险减仓类连续三个半日未成交进入开盘兜底"。
- **残留 B（止盈误挂风险类）**：take_half/clear 行携带
  `intent='risk'`，而引擎合同（band_engine v1 差异表第 7 条）
  明确 risk 类获得 K=3 开盘兜底、profit 类半日静默失效——
  AGENTS §1 同款要求。后果：止盈单成为常驻站立单且可获得
  强制开盘卖出（v3 的 400 笔卖出在 intent 列下全部为 risk，
  profit 类占比无法从成交台账直接区分；旧估"profit 类成交
  48 笔"归档不可复算，弃用）。
- **残留 C（归零事件残留）**：仓位被外部全部卖出后模块不清除
  旧事件，同一标的再买回时被旧触发日目标砸仓（复核实测多卖
  3,000 股）。
- 附带发现：**replay3 归档 runner 非执行版本**（运行后就地补丁
  计数函数，修改时间晚于运行结束 5 分半）——审计轨迹断裂的
  根因是 runner 自身未 pin。

**修复**（`single_name_rules.py` v3 版；引擎未动）：
- 整仓退出事件化：stop/protection 触发即冻结 `{target=0,
  source=触发日, reason}`，事件存活期间以冻结 source 重发
  `intent='risk'` 整仓卖单；活跃整仓事件吸收后续整仓触发（订单
  内容相同，保留首触发 source 保 streak）；减半事件被整仓事件
  替换（新 source 起新 streak）；仓位归零（含外部清零）即清除
  该标的全部状态；
- 类合同修正：`INTENT_OF_REASON` 映射——stop/protection →
  `risk`（兜底可用），take_half/clear → `profit`（半日失效，
  模块按事件重发维持退出意图，无强制开盘卖出）；
- runner 审计链：v4 起记录自身 sha（起止一致、运行中被改写则
  失败关闭）、git head/branch/dirty、依赖版本、峰值内存。

**验证**：新增测试 6 项（单元 4：整仓事件冻结 source、活跃事件
吸收替换、归零清扫、意图分类；端到端 2：`e4` 止损 K=3 武装链
[streak 1→2→3 → 开盘全量兜底 10,000 股]、`e5` 止盈腿反证
[同样三个半日不武装、反弹按重挂限价成交]、`e6` 外部清零后再
买回不被旧事件砸仓）；原 e4（减半腿武装）按新合同改写为 e5
反证。全仓 **686 passed**。基线以
`20260921T210100-baseline-replay4-9x4q2` 重跑：NOSNR 对照臂与
v3 核心输出逐位一致（manifest 内置断言比对净值曲线，log 文件
因新增 intent 列不同，见基线报告 §2）；止损 74 触发/74 完成
（v3 为 78 触发/72 完成，触发数由归档 86 行按 (symbol, 触发日)
归并而得、可复算，且无兜底）；退出层 −0.73 → −0.51pp。退出层跨版本归因见
基线报告 §6——二轮复核的"K=3 强制退出"假设被成交台账否决
（v2/v3 各仅 1 笔兜底成交），v2→v3 的卖出增量主体是 v2 坏状态机
