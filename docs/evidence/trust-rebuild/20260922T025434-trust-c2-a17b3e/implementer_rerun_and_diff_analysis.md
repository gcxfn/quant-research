## 3. 差异分类（零未解释差异）

### 3.1 逐笔舍入口径 vs 主引擎无舍入（表示差，非经济差）

- 现象：合同（C1 `fee_schema.rounding_rule`）规定参考实现在**每笔现金变动处**
  ROUND_HALF_UP 到分；主引擎全程 float64 **从不舍入**。两者对同一成交序列的
  日终已结算现金因此会漂移。
- 规模：10 个臂的日终权益差最大 **0.14 元**；首次出现 2015-03-06 ~ 2019-02-14；
  差异 >半分的天数占总交易日约 60%–97%。
- 归因：另跑一条**精确口径**（同 Decimal，但中间不舍入）与主引擎逐日比较，
  最大权益差 **3.6×10⁻¹⁰ 元**（float64 eps 量级），且 10/10 臂期末股数完全一致。
  这证明参考账本**没有遗漏任何成交/分红/送转事件**，逐笔舍入口径的一分差纯粹是
  「舍入位置」差，不是经济错误。
- 处置：不调宽容差。`ledger_reconciliation.csv` 的 `exact_equity_diff` 列逐日给出
  精确口径的残差，`note` 列标明该日差异是舍入位置差并附精确残差；审阅者可据此
  判定表示差是否可接受。

### 3.2 半分边界上的逐分差（表示差，非经济差）

- 逐笔净现金流：3319 笔中 **167 笔** 参考值与产物记录值相差 **恰好 0.01 元**，
  其余全部一致。
- 逐类费用：佣金 **1 笔**、印花 **7 笔** 相差 0.01 元；其余逐笔及**总额**一致
  （`fee_type_reconciliation.csv`）。
- 成因（已逐笔核对）：成交名义 `price×shares` 或其费率乘积恰好落在半分边界
  （如 `x×0.001` 的第 3 位小数为 5，或 `x×0.0001` 的第 4 位为 5），float64 只能
  存到边界**略下方**，于是把该值四舍五入到分时向下取，而精确 Decimal 值向上去；
  另有「分别舍入两费后求和」与「对和再舍入」的 1 分差。示例节点：
  - `F000414`（2019-02-01, sh.600062, sell）：名义精确 16305.00，印花 16.305 →
    参考 16.31，产物 float 16.304999999999998 落到 16.30；该笔净额两边一致。
  - `F000034`（2016-04-12, sz.002031, buy）：佣金 5.915 → 参考 5.92，产物 5.91。
  - `F000010`（2016-03-01, sh.600493, sell）：参考净 55283.13 / 产物 55283.12，
    因产物 `fees_total`=60.88 与「分别取整之和」60.87 差 1 分。
- 处置：全部逐条登记在 `ledger_reconciliation.csv`（`record_type=fill`），
  金额上限 0.01 元，未解释金额差为 0。

### 3.3 公司行动：全部逐分/逐股一致

- 146 条公司行动事件（21 送转 + 125 分红）全部对上：送转比例 `ratio_diff` 全 0
  （对照沙箱 `split_factor`），分红现金 `cash_diff` 全 0（对照沙箱 `dividend` 的
  每手金额 ÷ round_lot × 除息前持股），送转后股数 `shares_diff` 全 0（对照参考
  账本逐 clip half-up 变换结果）。
- 复算口径取证：`sz.000723` 2017-06-16 ratio 1.8（1600→2880）、`sh.601229`
  2017-07-20 ratio 1.3 且每股分红 0.5（每手 50/round_lot 100）等均逐项吻合。

### 3.4 期末持仓：全部一致

10/10 臂的期末逐证券持股与 `*_clips_final.parquet` 完全一致（差异行 0）。

## 4. 复算中发现的两处引擎语义（登记，不自行修改主引擎）

1. **估值 mark 的 carry-forward**：主引擎 `mark_close` 用**可交易**（`tradestatus!=0`）
   行的官方 close 做"on/before day"的 carry-forward；停牌日的原始行 close 被跳过。
   参考账本初版直接用当日原始 `close`，导致 NOSNR-bin 等 3 个臂出现 18–544 元的
   市值差；改为同一 carry-forward 口径后精确口径残差回到 float eps。
   **证据**：`band_engine.py` `mark_close`（"Official close on/before day"）与
   `_build_series` 的 `trade_close`（tradestatus 掩码）；示例 `sz.002437`
   2018-07-18 raw close 6.19、停牌 carry-forward 6.20。合同
   `contract_snapshot.valuation.mark` 只写"官方日线 close"，未写明停牌处理，
   属**合同文字欠明确**，本阶段按引擎实现事实对齐并在报告登记。
2. **同一 session 内卖出款不可用**：与 C0 `settlement_delay` 一致；参考账本对
   "同上午买入依赖同上午卖出款"会报 `SettlementTimingError`（测试 E4）。
   主引擎 buy 段在卖出记账前评估可用现金，行为一致；10 个臂实际成交中未出现该冲突。

## 5. 阻断项
