## 必须修改

### R1 / P1：推荐 worker 绕过事前冻结数据与代码契约

位置：`source/new/t3_l0_worker_20260913.py:816`（`cmd_run`），尤其 870–884 的无装载提前返回、888 起装载和 958–960 收尾；交接 §7.1。

worker 不读取 `run-identity.json` 或 `data-manifest.json`，也不调用批跑器的 `_verify_identity` / 原始文件收尾核验。它在启动后自建当前代码和 bundle 身份，只能识别本 session 后续输入变化，不能证明第一次运行的数据就是事前登记数据。亲测：临时目录仅放一条清单及一片，完全没有冻结 identity/manifest，真实 `W.main` 仍到达装载器（装载器被哨兵异常替代，未读取研究数据）。

因此，只把 worker 加入 `T3_SCRIPTS` 仍不够：登记了却不消费，同样无法拦截登记后变更；只校验内存 bundle 也不满足计划 §4 的启动/恢复与收尾原始文件校验。所有片已完成时，`run` 还会直接跳过当前数据核验。

**最小修复**：worker 复用批跑入口的冻结代码/清单/数据校验，在装载前、恢复前及收尾调用；检查点绑定冻结 manifest 摘要。已完成片的纯工件核对可保留无装载路径，但应明确是历史工件验证，并与需要核当前数据的 `run` 分开。worker 纳入冻结脚本集合后，用新批次、新输出根登记，勿改写 `-12`。新增“无冻结身份、登记后改原始数据、登记后改 worker、收尾数据变化”负例；已有 F1/F2 单元测试继续复用。

### R2 / P2：证据新鲜度仍由 mtime 推断，且漏掉实际依赖

位置：`source/new/t3_perf_package3_20260913.py:102` 起的 `EVIDENCE`，及后段 `mt = os.path.getmtime(src)` / `dep_state[rel] = sha256_file(p)`。

打包器将**打包时**的源码 SHA 写入 `evidence_provenance`，没有与**测试运行时**记录的 SHA 对比；mtime 早于证据不能证明该字节版本被测试过。例如复制保留时间戳的另一版本后，仍可把旧测试绑定到新字节。此问题不说明当前 59 件已遭污染，而是 `evidence_all_newer_than_deps=true` 不能承担所宣称的内容证明。

还有具体漏项：`identity-tests.json` 的依赖没有 `experiments/r0_audited_runner.py`，而 F2 测试实际依赖其 `verify_data_manifest`。修改这个核心校验器不会让该证据失效。GPU 真实样本依赖 `director.train_test`，GPU 证据依赖表也未纳入 director。

**最小修复**：在现有测试输出中记录运行起止的源码/生成器/输入摘要；打包时逐项与其比较，mtime 仅作辅助。补齐实际依赖，至少上述两项；A/B 双侧分别绑定。补一个“字节改变但时间戳不变仍拒绝”的负例。只重跑受影响证据，不要求因文档改动全包重测。

### R3 / P2：GPU 决策混用了计算阶段、含装载流程和不同配置

位置：交接 §2.3、§5、§7.1；`gpu-bench.json::adoption_criteria`；`source/new/t3_perf_gpu_bench_20260913.py:629`。

独立核算保存的同源原始计时：`train_test=2.292s`，CPU 衰减 `1.042s`，GPU block=128 衰减 `0.629s`，不分块 `0.489s`。替换估计分别为：

| 范围 | block=128 | 不分块 |
|---|---:|---:|
| 真实 285 股衰减段 | 1.66× | 2.13× |
| train_test 计算阶段估计 | 1.220× | 1.318× |

0.455 是 **train_test 内**衰减占比，绝非含装载端到端占比；它与“装载占 wall 82.5%”不是同一分母。2.72–2.88×来自全池形状的合成面板，不能表述为两套真实配置均通过热点门槛。1.32×虽用同源真实计时算得，但取较快不分块路径，且不含装载、身份核验、聚类、落盘、初始化，也不是实际 CPU/GPU pipeline A/B wall。

**裁决**：当前样本不采用 GPU 成立；“全池也不值得”尚未证明。真实 block=128 连热点 2×都未达到，不分块计算阶段也未到 1.5×。按实际运行配置分别应用判据，不将最佳热点和另一配置的总耗时组合。更正文档为“样本计算阶段估计，GPU 保持原型；全池待测”。交接预测衰减占比 0.5–0.55 也应撤为无证据假设：其他统计同样可能排序，不能仅凭 S log S 推断占比上升。

### R4 / P2：交接的 CPU 回退命令不会切换 worker 后端

位置：交接 §7.1“旧 CPU 回退命令”；`source/new/t3_l0_worker_20260913.py:243`、1259。

亲测真实参数解析和 `_apply_runtime_config`：清除 `FACTOR_MINER_NUMPY` 后执行默认参数，requested/actual 仍为 numpy，环境变量重新变成 `1`；显式 `--backend pure` 才得到 pure。因此“清掉变量后重跑同一 run 命令”不适用于推荐入口。

**修改**：worker 命令显式加 `--backend pure`，另用新输出根；如要关闭面板缓存再加 `--no-panel-cache`。这只是当前实现的纯 Python 统计路径，并不是恢复优化前源码。批跑 director 与 worker 的配置机制分开说明。正式运行前补一次小规模新进程 CLI 启动/中断恢复/显式回退验证；不需要运行全部 1430 项才能验证命令。

## 优化建议与最小补测

1. 先修 R1/R2，保留单进程一次装载与 B1/B2/B4；不新增并行进程、框架或依赖。数据与代码冻结是正式性能比较的前提。
2. 单列身份校验耗时。现在 `_input_identity` 计算内容摘要，`director.run_real_pipeline` 每片又重算一次，20片会增加20次完整 bundle 扫描。不要直接删安全闸；先计时，再用内部不可变已验证 bundle 复用摘要，外部 preloaded 入口仍须核验。
3. B3/B5/D 以285股样本暂缓合理，不能写成全池优化方向已被否定。后续范围获准时，先选冻结清单内少量有代表性的公式测完整股票截面，记录 wall、RSS、系统可用内存与分阶段计时，再决定数组出口、有限公共表达式缓存或GPU。全量取消状态未恢复，本审不执行该试跑。
4. 训练尾端补一个小型哨兵负例：只改变2023以后价格，2020–2022的月IC及六期限衰减完全不变；同时核末尾合法日期计数与常数截面的 None/n。现有 immature_month_* 检查的是结果行，不能独立证明统计函数不越界读标签。当前源码 `D-h` 截断未发现具体越界缺陷，此处是补证建议，非已证实未来函数。
5. GPU缺失/inf的旧反例属实。当前两趟稳定排序在本审四组 CPU tensor 算法核算中与 NumPy平均秩精确一致；CUDA对抗/块边界/OOM证据复用包内记录，本审未重跑整套GPU性能基准。无需为已关闭反例增加第三层全面验证。
