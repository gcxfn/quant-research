## 2. 第一轮发现（7 项）

### R1-1：把 h=5 持有期收益当作逐日收益连续复利

**证据**

- `experiments/p4_screen.py:127-159` 的 `_portfolio_metrics()` 明确按逐日收益逐项复利，并以记录数按 252 日年化。
- `experiments/p4_screen.py:232-241` 每个信号日生成一个 h 日十分位收益。
- `experiments/p4_screen.py:304-315` 又把每日滚动产生的 h=5 收益直接传给逐日净值函数。
- `docs/plans/p4-factor-research.md:56-58` 要求报告十分位组合净值、年化、夏普和回撤，但没有授权把重叠 5 日持有期收益视为单日收益。

**反例**

若每个信号日的 h=5 收益均为 1%，代码会按 `1.01^252-1` 得到约 1127% 年收益；1% 实际是五交易日收益，不能每天完整复投。使用非重叠 5 日轮次时，同量级年收益约为 `1.01^(252/5)-1`，两者数量级不同。

**如何改变结论**

直接放大 total return、年化、夏普和回撤路径，并传入 Gate B1；候选可能由不通过变成通过。

### R1-2：Gate B2 的显著性使用非重叠轮次，但期望净收益使用全部重叠标签

**证据**

- `experiments/p4_barrier_screen.py:185-209` 只为显著性筛出同股票非重叠轮次。
- `experiments/p4_barrier_screen.py:243-284` 的 p 值基于这些非重叠轮次。
- `experiments/p4_barrier_screen.py:487-505` 却把所有逐日重叠标签累计进概率、净收益和持有期统计。
- `experiments/p4_barrier_screen.py:399-417` 的 `expected_net_per_round` 由上述全量重叠样本计算。
- `experiments/p4_barrier_screen.py:539-550` 最终 B2 同时使用非重叠 p 值和全量重叠期望值。
- 预登记计划 `docs/plans/p4-factor-research.md:60-61` 规定障碍指标及统计推断按非重叠轮次组织。

**反例**

同一股票连续五天发出高度重叠的同方向信号时，一段真实价格路径可被期望值重复计入五次，却只在显著性中保留一次。重复的盈利或亏损路径会按信号密度改变期望值，而不是按独立交易轮次改变。

**如何改变结论**

Gate B2 的“显著超过先验且单轮期望为正”不再来自同一观察总体，可能错误通过或错误淘汰。

### R1-3：预登记 24 个主检验被扩展为 48 个候选列检验

**证据**

- 计划 `docs/plans/p4-factor-research.md:31`、`:69` 冻结为 6 因子 × 4 止损档 = 24 个主检验。
- `experiments/p4_screen.py:28-34` 把 F1–F6 的多个构造展开为 12 个候选列，另含 C1/C2。
- `experiments/p4_barrier_screen.py:461-475`、`:519-565` 按每个因子列而非每个预登记因子组执行 Gate B。

**反例/实测口径**

F1 2 列、F2 1 列、F3 2 列、F4 2 列、F5 3 列、F6 2 列，共 12 个候选列；乘以 4 个止损档为 48 个候选主检验，而非冻结的 24 个。C1/C2 另作阴性对照，不计入这 48 个。

**如何改变结论**

实际搜索空间翻倍，但仍按 24 个检验的 Bonferroni 参考线解释，显著性声称与预登记不符，增加偶然存活候选。

### R1-4：2019 预热期进入因子相关矩阵等选择统计

**证据**

- 配置 `configs/p4-factor-research.json:7-9` 冻结 warmup 从 2019-01-01 开始，选择窗从 2020-01-01 开始。
- `experiments/p4_screen.py:589-617` 从 warmup_start 构池，只截断选择窗尾，没有截断选择窗头。
- `experiments/p4_screen.py:185-203` 对 factor records 的全部日期循环。
- `experiments/p4_screen.py:243-259` 明确将“全日期”用于因子相关统计。
- 计划 `docs/plans/p4-factor-research.md:27` 和 `:54-59` 规定筛选统计只用 2020–2023 选择窗；2019 只允许预热。

**反例**

若两个因子在 2019 年高度相关、2020–2023 不相关，当前相关矩阵会混入 2019 关系，并可能据此错误执行“冗余因子只留 ICIR 高者”。

**如何改变结论**

会改变相关矩阵以及候选去冗余结论。IC 因缺少 2019 标签通常不会同样受影响，但这不能使相关筛选合规。

### R1-5：Gate A 对预登记负向因子使用带符号 ICIR，导致负向有效因子必然失败

**证据**

- `experiments/p4_screen.py:271-287` 计算 `icir = mean_ic / std_ic`。
- `experiments/p4_screen.py:363-369` 对 mean IC 使用绝对值，却要求原始 `icir >= 0.3`。
- 计划 `docs/plans/p4-factor-research.md:41-48` 明确预登记了多项负向假设；Gate A 在 `:65` 要求 `|mean rank IC|` 达标并检验方向一致性。

**反例**

一个完全符合负向预登记、`mean_ic=-0.03`、`std_ic=0.05`、四年中三年为负的因子，得到 `ICIR=-0.6`。其绝对强度和年度方向都达标，但代码仍因 `-0.6 >= 0.3` 为假而淘汰。

**如何改变结论**

系统性淘汰预登记的负向因子，直接改变 Gate A 存活名单及后续 Gate B/C 是否运行。

### R1-6：平均持有会话数采用零基索引，整体少记一个会话

**证据**

- `experiments/p4_barrier_labels.py:158-179` 返回循环变量 `sess`，首个扫描日为 0。
- `experiments/p4_barrier_labels.py:285-300` 将该值写入各止损档的 `*_sessions`。
- `experiments/p4_barrier_screen.py:498-504` 直接累计这些值，`:415` 输出平均持有会话数。
- 计划 `docs/plans/p4-factor-research.md:60` 要求报告“平均持有会话数”。

**反例**

第一可退出会话触价会报告 0，会话路径第 5 日退出会报告 4；按自然持有会话数应分别为 1 和 5。

**如何改变结论**

直接改变报告数字及持有期解释。虽然它不单独改变 win/loss，但与声称的会话口径不符。

### R1-7：AGENTS.md 的 P2/P3 基线数字落后于最终工件和 decisions 真相源

**证据**

- `AGENTS.md:13` 仍写 P2 MATCH 87、已配对价差 +2627.12。
- `docs/decisions.md:75`、`:82` 已把最终有效基线更新为 MATCH 86、DQ 3、递延 1、净差 +2637.11。
- `AGENTS.md:14` 只列旧版 P3 full 窗 G1/G5 摘要，未反映最终工件 40 个窗口读数范围。
- `docs/decisions.md:43` 记录最终 P3 工件 40 个 total_return 全负，范围 −71.5544%～−1.5825%。

**反例/实测证据**

最终工件：

- `target_orders_20260908_002408.json`：149 单；
- `full_compare_20260908_004452_rate_0p005.json`：MATCH 86、DQ 3、递延 1、已配对净差 +2637.11；
- `p3_p1pool_20260908_015419.json`：8 组 × 5 窗共 40 个 total_return 全负。

**如何改变结论**

不会改变代码计算，但会使后续研究从错误基线出发，属于冻结记录与最终真相源不一致。P2/P3 本身仍维持 PASS。

## 3. 第二轮新增发现（4 项）

### R2-1：障碍标签允许新买入股票在入场当天止盈/止损，违反严格 T+1

**证据**

- `AGENTS.md:5` 明确规定“新买入严格 T+1”。
- `experiments/p4_barrier_labels.py:145-180` 从 `start_idx` 当天扫描障碍。
- `experiments/p4_barrier_labels.py:285-300` 把入场日 `i+1` 直接作为 `start_idx`。
- `tests/test_p4_barrier_labels.py:202` 将“入场日双触记负”固化为预期行为。
- 计划 `docs/plans/p4-factor-research.md:29-33` 同时写了 t+1 开盘入场及 t+1…t+5 扫描；它与项目级严格 T+1 卖出纪律冲突，应以项目边界为准修正研究路径。

**实测反例**

输入：入场日 open=100、high=103、low=97、止盈=102、止损=98，状态可交易。当前函数返回：

```text
('loss', -0.020000000000000018, sessions=0, exit_price=98)
```

即新买入股份在入场当天按 98 元卖出；真实 T+1 下当天不可卖。

**如何改变结论**

所有入场日触障碍样本的 win/loss/timeout、净收益和持有期都会改变，进而改变 Gate B2。

### R2-2：“扣费后”十分位多空价差中费用被代数抵消

**证据**

- `experiments/p4_factor_research.py:258-266` 对每只股票生成 `gross - cost_rate` 的 fee label。
- `experiments/p4_screen.py:110-124` 计算顶组 fee label 均值减底组 fee label 均值。
- `docs/plans/p4-factor-research.md:57` 声称该组合为“顶减底，等权，扣费”。
- `docs/plans/p4-factor-research.md:66` 要求 Gate B1 使用扣费后经济结果并覆盖双边费用。

**实测反例**

顶组毛收益 +0.3%、底组毛收益 0%、每侧费用 0.2%：

```text
gross spread       = +0.3%
代码 fee spread    = +0.3%
双腿实际扣费结果   = -0.1%
```

原因是 `(top-fee) - (bottom-fee) = top-bottom`，共同费用完全抵消。

**如何改变结论**

不足以覆盖双腿费用的毛优势可被报告为扣费后盈利，并可能错误通过 B1。

### R2-3：Gate B block bootstrap 在常量小样本上退化为最小 p 值

**证据**

- `experiments/p4_barrier_screen.py:212-240` 用样本均值中心化后做 block bootstrap。
- 常量正超额序列在 `:227` 中心化后全部为零，bootstrap 均值不可能达到正的原观察均值。
- `docs/plans/p4-factor-research.md:61` 要求日期聚类稳健检验并披露有效样本量。

**实测反例**

固定 B=2000、block length=5：

```text
5 个相同正超额日：   p = 0.0004997501249375312
50 个相同正超额日：  p = 0.0004997501249375312
```

只有 5 日的样本与 50 日样本得到完全相同的最小 p 值 `1/(B+1)`，样本量信息消失。

**如何改变结论**

极小、零方差的可达样本可能被宣告高度显著并错误通过 B2，甚至低于 Bonferroni 参考线。

### R2-4：P4 中间缓存未实现冻结 §10 要求的配置与输入快照身份键

**证据**

- `docs/plans/p4-factor-research.md:98` 明确冻结：缓存键必须包含配置与输入数据快照哈希，工件只新增。
- `experiments/p4_screen.py:519-542` 加载时只检查 run_state 和两个缓存文件路径。
- `experiments/p4_screen.py:545-566` 保存的状态没有配置或输入身份。
- `experiments/p4_screen.py:574-587` 发现缓存后直接复用，不重新构池或核对本轮配置。

**可复现路径**

先用配置/数据 A 在某个 out-dir 生成中间结果，再修改费用、日期窗、参数或输入快照并对同一 out-dir 重跑；程序会直接加载 A 的 factor/label records。

当前默认目录尚无中间缓存，因此没有证据表明现有工件已被该问题污染；但这是正常断点续跑路径可达的确定性冻结纪律违反。

**如何改变结论**

配置 B 可能得到由配置/数据 A 生成的筛选结果，直接破坏复现性和冻结参数有效性。

## 4. 是否需要重跑数据

结论：**不需要重新抓取或重建底层数据；需要在修复后重跑全部受影响的 P4 派生数据和筛选工件。**

| 层级/工件 | 是否重跑 | 理由与边界 |
|---|---|---|
| 原始行情、本地用户数据集、baostock 状态/退市数据 | 否 | 两轮复审没有发现底层数据源错误；禁止无理由联网重抓。 |
| P0 数据覆盖探查 | 否 | 当前覆盖门禁复核通过；不存在要求重建原始数据的发现。 |
| P1 历史时点池独立工件 | 否 | P1 语义维持 PASS。P4 正式运行仍应照常从冻结 P1 构池函数重建本轮输入，而不是重做 P1 研究线。 |
| P2 目标订单、分钟全对照 | 否 | P2 代码和最终工件未受 P4 问题影响。Gate C 若产生存活候选，只对新候选按计划做分钟抽验。 |
| P3 八组机制归因 | 否 | P3 基线未被推翻；无需重跑 40 个窗口。 |
| P4 factor records | 是 | 选择窗过滤、候选定义/方向和缓存身份修复后必须从冻结输入重新生成。 |
| P4 线性 fee labels | 是 | 费用及 h=5 收益口径会改变 B1 数字。 |
| P4 `p4_screen` 全部 IC/十分位/相关矩阵/Gate A | 是 | R1-1、R1-3、R1-4、R1-5、R2-2 均影响该层。 |
| P4 barrier labels | 是 | T+1 和持有会话修复会改变逐样本标签。 |
| P4 Gate B | 是 | 非重叠总体、期望值及 bootstrap 修复会改变显著性和经济结论。 |
| 既有 P4 intermediate 缓存 | 不得复用 | 修复后的首次正式运行必须重建；后续缓存须通过冻结的配置+输入身份校验。旧文件可保留作历史证据，但不能混入新结论。 |
| 小样本 sanity 工件 | 是 | 先用修复后代码确认阴性对照不放行和四档 Gate B 行为，再启动全池选择窗。 |
| Gate C | 条件式 | 只有修复后 Gate A/B 有存活者才运行。 |
| 2024+ Gate D 验证窗 | 现在不跑 | 继续冻结；只有 Gate C 存活并完成独立复审后才允许一次性开启。不得用本轮修复为理由提前查看或反复测试。 |

### 修复后的最小合规重跑顺序

1. 为 11 项发现补充能够复现失败语义的单元测试；尤其要改掉“入场日双触可退出”的现有预期。
2. 修复 P4 因子/筛选、障碍标签、Gate B 和缓存身份；同步澄清预登记的 6 组/12 构造及多重比较口径，不得运行中临时选择有利定义。
3. 运行 P4 定向单元测试、全量 `unittest` 和既有 smoke。
4. 仅使用 2020–2023 选择窗，重新生成 factor records、linear labels、barrier labels、IC/十分位/相关矩阵及 Gate A/B 工件；不读取旧 intermediate。
5. 阴性对照显著、数据门禁失败或任一缓存身份不一致时 fail-closed 停止。
6. Gate A/B 无存活者，记录“本轮无候选”并停止；有存活者才进入 Gate C。
7. Gate C 通过并独立复审后，才允许一次性打开 2024+ Gate D。
