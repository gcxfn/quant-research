## 1. 本轮发现

### W2-01 / P1：MTM 估值被当作实际卖出，释放不可卖的资金

位置：`experiments/factor_miner/backtest.py:331` 附近 `_holding_return` 的 MTM 返回；`:550–585` 的持仓调度与退出循环。

退出超限时 `_holding_return` 返回 `mtm_deferred_exit` 和最后可得收盘日。调用者不区分实际成交与估值，把该日存入 `sale_j`，随后对所有到期 sale_j 收卖出税佣、增加现金、删除持仓。

直接合成反例：A 在 02-03 入场，自 03-02 起直到样本结束一直 `tradestatus=0`；末期仍输出 `exit_actual={a:2020-06-02}`、`sell_fees=37.5`、`exit_proceeds=49962.5`、`n_still_held_into_next=0`，尽管当天仍停牌。`exit_status=mtm_deferred_exit` 的披露不使这笔卖出成立。

要求：实际退出事件与 MTM 估值分离；只有确认成交才设置卖出日期、扣卖出费用、释放本金。未退出仓位保留数量、市值和资金占用，期末披露未平仓。增加“持续停牌直到样本末”的端到端断言：无卖出流水、无卖税、未平仓非零。

### W2-02 / P1：开盘边界估值使用当天收盘，且末期没有兑现收盘估值约定

位置：`experiments/factor_miner/backtest.py:275–291`、`:587–591`。

`_mark_price` 先取当日 open，缺失则取当日 close，再往前回溯。该函数用于“下一入场日开盘”边界：当日收盘在该时点尚不可知。反例中前一日 close=10、边界日 open=None/close=20，函数返回20，提前将当天盘中涨幅计入上一期，并用于本期期初权益分母。

同时，最终期仍调用相同的优先 open 函数；最后一天 open=10/close=20 返回10，与预登记“最终期按最后可得收盘”相反。

要求：估值接口显式区分开盘边界和样本末收盘边界。前者只能取当时可得 open 或严格早于该日的有效 close，后者取截止日收盘；记录估值时点与陈旧程度。测试必须使用 open≠close 的数据，不能只用平价行情证明时序正确。

### W2-03 / P1：组合与基准收益归属不一致，净边际仍比较了不同时间区间

位置：`experiments/factor_miner/backtest.py:627–639`，以及后续 `paired_proxy/net_edge_proxy` 汇总。

组合已经按月初边界 MTM 拆分递延收益，基准仍调用 `_holding_return`，将月后实际退出的全部收益归入原月。`n_paired_months` 只对齐月份记录，没有对齐记录里的经济时间区间。

独立反例只有 A 一只股票：入场10，03-02开盘9且跌停不可卖，03-03开盘11卖出。第一期组合 gross=-10%，基准 bench_gross=+10%，同一资产同一期出现20个百分点差异，原因完全是基准提前包含后一天的恢复收益。第二期两者分别约+22.22%与+11.11%，交易开始时点和资金轨迹也不同。由此计算的17/27bps净边际仍进入家族门禁。

要求：先明确基准的可交易持仓/现金规则，再让组合与基准使用相同日历边界和递延估值方式。基准不能继续直接使用完整未来交易标签充当当月收益。用单资产、相同初始持仓及相同交易规则验证毛收益一致；差异若来自不同交易规则，须显式归因，不能来自时间归属错误。

### W2-04 / P2：未成熟状态只在入场月记账，下一月无新信息却恢复为正常零收益

位置：`experiments/factor_miner/backtest.py:502`、`:540–548`、`:612–624`。

`n_immature` 每月清零，只在新增 `incomplete_label` 仓位时增加，没有从跨月旧仓状态重建。反例将 A 从03-02起的价格行全部移除：第一期为 `immature, n_immature=1, net=None`，下一期却为 `normal, n_immature=0, net=0`，期间没有任何新报价或成交。

要求：未成熟/不可估值状态随持仓跨月传递，直到明确满足恢复条件。若决定允许陈旧价估值，应另行明确口径并披露，不能仅因月份循环切换就自动恢复为有效零收益。此问题与“真正无仓位现金月=0”的已完成修复不同。

## 3. 开放项与配套材料裁决

1. **双路径一致异常不豁免为成功覆盖。** 它可以证明对某项非法输入的拒绝行为一致，不能证明该冻结候选完成了数值评估。若正式输入触发异常，应修复实现/数据或按预先冻结的异常政策登记处置，重验完整集合；不得见到结果后删候选、缩N或将其改写成PASS。送审§6.3仍写“round-1 R0 numpy长度异常”：round-1证据为R0仅REV_cond_15空序列、两条长度异常在R1，且当时扫描是默认纯路径，须更正。

2. **外部现金归一模型只作为明确披露的研究模型审议。** 当前每期有注入/撤回、买费可挂负现金，不等于固定20万元无融资账户。新产品目标已为0..N只、程序按冻结规则推荐权重，应将旧Top15文字改成历史示例，实际费用按每笔金额及最低佣金计算。20万等权分为k>10份会低于2万元，但不等权时即使k≤10也可能有小于2万元的订单。持仓规则须进入后续组合精测冻结。本包不改17/27/37历史阈值。

3. **registry历史限制应如实界定。** fresh-dict重放在已有history后增长历史可列后续修复；get返回对象引用，原地修改后upsert无法保存修改前快照，不能把“同对象不增长”称为历史留痕已解决。若上层台账承担历史保存，需提供对应记录映射后再验收全链身份。TW-4/5的重复/非法ID拒绝可单项闭合。

4. **MT只接受为尚未取得实证结果的工具交付。** 驱动器自测通过，但本次未执行276条变异、未确认漂移后的锚点。共享可写工作区的快照恢复不应与其他写代码任务并行；FINAL_TREE_CLEAN是事后检查，无法防止把并发写入覆盖掉。实际执行应使用独占隔离副本，并先确认未变异基线测试通过；否则已有红测会被误计成KILLED。MT当前不作为运行门禁，亦不报杀伤率。

5. **EX1/EX2/EG为索引和审查线索，不是新的独立裁决。** 本次检查了文档和引用结构，未逐一复算109条实验及20死区。EG仍含已撤回的“R0九结构”表述，应标注快照截止与后续更正；用于R1机器比对的dead_zones及输入身份必须受控保存后再审。不能将历史缺少独立裁决的项目仅经索引转换成独立PASS。
