## 修改意见（按优先级）

### F1 / P1：worker没有绑定实际输入内容

位置：性能包 `source/new/t3_l0_worker_20260913.py:285–329`，恢复入口807以后。

`_input_identity`仅摘要收盘长度、池掩码True数量、证券/日期轴和元数据，没有价格值、其他因子字段值或逐日期池掩码。亲测三个独立扰动：close从11改999、volume从2改999、两日期True/False交换，输入摘要全部不变。因此部分完成后的续跑即便重新装载，也无法识别这类改变；数据version字符串相同就可能混批。已有`input_digest_rejected`测试扰动摘要声明，不能证明真实输入变化可被检测。

建议：复用已有原始输入清单及内容摘要验证能力，绑定全部实际消费的数据根/批次与输入文件；或对实际bundle字段和池掩码做规范内容摘要。摘要在装载时只计算一次，避免每候选扫描。恢复与新片必须验证同一可信输入身份。补上述三个负例与合法同输入续跑即可。

### F2 / P1：-11批跑入口冻结的是数据清单文件，而非当前数据

位置：`experiments/t3_l0_batch_20260913.py:210–236,370–379`。

`_verify_identity`只检查`data_manifest.json`自身SHA；实际run直接启动director.pipeline，未走已有r0_audited_runner的数据根内容重算与收尾核验。director的代码洁净检查不能替代数据字节校验。原始数据改变而清单JSON不变时，这层仍接受旧身份；结果data_version亦是批次名称字符串。

建议：直接复用r0_audited_runner现有数据身份核验函数，启动/恢复及收尾核对清单引用的实际文件，并确保新增消费数据批已入清单。不要新建第三套身份框架。两条入口应遵守同一输入契约，但先分别修复，不因优化包测试通过而给旧批跑器签PASS。

### F3 / P2：A/B比较器会把容差一致标成精确一致

位置：性能包`source/new/t3_perf_compare_ab_20260913.py:26–57,136`。

`_cmp_exact`对容差内的浮点差异只增加counter，不增加diffs，而最终PASS_EXACT只看diffs/identity/决定性差异。亲测0.1与0.1+1e-16：diffs为空、float=1。因此今后的衰减/分组收益等小差异可能被误报逐位相同。本次保存A/B的float=0，此缺陷不推翻当前样本无差异事实。

建议：精确比较与容差报告分开；float>0时不能签PASS_EXACT。补一个容差内差异负例即可。

### F4 / P2：性能推算仍存在算术与口径问题

285股/20候选保存计时：旧计算20.766秒，新9.498秒，计算段2.19倍；加装载后分别79.703/68.244秒，仅约1.168倍。长驻多片可继续摊薄装载，但全池20片尚无实测。

`baseline.md`将装载0.30–1.24小时、计算5.54小时合计推算为约5.9–6.8小时，却用不同分母得到4.4%–17.9%装载占比。同一模型应为0.30/5.84=5.14%至1.24/6.78=18.29%。§4.2声称中点装载33%也与表内数值不一致。13分钟记录与线性外推69.2分钟不能构成可靠上下界，只能作为情景假设。

建议：区分计算段实测、含装载样本实测、全量假设估计。按下述路线验证CPU去重复与局部GPU批量统计；真实性能试跑沿用用户取消全量后的范围约束。全池代表样本测量须计峰值RSS/换页，不能用GPU排序倍数推断完整挖掘耗时。

### 5. B：CPU确定性优化，先做小差量

**B1：消除Spearman的两次冗余排序。** 位置`stats_np.spearman_np`。现代码计算`mx/my`时对`rx/ry`再次排序并累加；平均秩总和始终是`m(m+1)/2`，故`mx=my=(m+1)/2`。本股票规模下整数/半整数和精确可表示，保持其余`sxx/syy/sxy`累加顺序，可争取逐位等价。覆盖并列、全相等、±inf、NaN/None成对剔除、空截面与单样本；不顺手把`cumsum`改为另一种归约。

**B2：装载内部去重复。** 按既有profile定位`listing_bounds/stock_basic`整表反复读取及`load_raw_daily/user_qfq_rows`每股重复读取。每次装载先建一次基本信息索引，同一证券同一来源/窗口价格只解析一次，资格判断和bundle构造共享读取结果。保留历史上市/退市、日历、停牌、复权及窗口隔离，不用今日名单替代。优先装载作用域缓存，释放原始临时对象；不加永久全局缓存导致跨批污染。

**B3：内部保留数组。** `operators_np.evaluate`目前将ndarray转list，`stats_np._series_matrix`再转数组。新增最小内部数组返回选项，旧公开入口默认返回类型保持；NumPy统计、截断与GPU上传消费同一只读数组。先接这几个调用点，不重写全部StockRows或bundle协议。None/NaN转换仅在既有兼容边界处理，按列矩阵布局记录一次必要重排，避免每期限转置拷贝。

**B4：及时提取月度聚类输入。** `director.evaluate_units`保留通过者日频`factors`，`run_real_pipeline`随后只为聚类调用`factor_monthly_values`。为L0 worker增加明确的紧凑内部路径：单候选完成所需日频统计后，使用同一现有函数和同一轴/池生成月度数据，再释放日频因子。原调用方若依赖返回的完整`factors`仍走旧默认，不能偷偷换返回语义；聚类结果/配对相关应与旧路径一致，聚类不用于少算候选。未通过候选也要先完成全部冻结统计输出再释放。

**B5：基础面板和前向收益复用。** 一个长驻worker服务20个逻辑分片，收盘/池矩阵复用；前向收益按日期块/期限有限缓存。月频收益也可同输入身份共享。不得跨不同成对有效集合复用最终收益秩；使用股票×日期矩阵还是日期×股票矩阵由热点决定，不同时保留多份完整副本。

### 6. C：GPU先做批量排名，逐步扩到IC衰减

**框架选择。** 首选已经可用的PyTorch CUDA，只在隔离环境新增一个局部统计模块并接worker显式配置。当前安装事实使其比另装CuPy更省工作；不同时维护两套GPU实现。默认CPU保持，显式请求GPU时记录实际后端，CUDA不可用不能静默标GPU成功。

**支持范围。** CPU继续负责数据读取/PIT、公式求值、冻结bootstrap、门槛和账本；GPU最初仅处理同一因子在多个日期、期限上的截面排序与平均秩，后续才考虑相关归约。月IC沿现有CPU路径留作第一版权威门槛输入。保留全部六个衰减期限`1/2/3/5/10/20`和合法日期，不能改为只算月末或只算通过者。

**数据流与分块。** 初始一个GPU worker，每次一个因子、一个期限、约128个日期；每个日期块保留全证券截面，不能按股票分块各自排名。收盘/池及前向收益按需留显存，因子每批上传后消费多个期限，最终只回传必要秩/统计，不逐股票发起GPU调用。块大小OOM时有限减半，仍失败则整候选转冻结CPU并记录，不减少样本。前向收益边界仍由训练轴决定，不越界读取2023标签。

**成对有效样本。** 逐期限逐日期先生成`PIT池 ∩ 因子非NaN ∩ 有效前向收益`掩码，遵守现有Spearman保留±inf的语义。非法价格与前向收益依旧按现有函数处理。排序时用独立有效位区分缺失填充值和真实+inf；每行有效数不足2、常数秩的结果按CPU返回None。不能以`isfinite`替代旧统计NaN规则，也不能误把CS_RANK的有限值规则移植到Spearman。

**平均秩算法。** 同行有效值稳定排序，识别相等游程的起/止位置，为该组赋`(首位秩+末位秩)/2`，再按索引散回原证券顺序。有效数、游程分组与秩必须精确一致。初版允许分别计算每期限的排名；只有完整有效集合相同才可共享，不能直接取全池秩的子集充当子集排名。

**两步处理归约差异。** C1先采用“GPU排序/平均秩＋CPU沿原顺序归约”：回传秩，在CPU用现有累加顺序求相关与跨日期均值，优先获得精确对照。C2仅在实测回传/CPU归约成为热点后尝试GPU相关归约，以减少传输；必须记录与CPU的数值差异，不能因GPU可重复就签逐位相同。冻结bootstrap随机消费、种子与门槛不改；不使用FP32、TF32或混合精度冒充等价加速。

**正式使用边界。** 如果C2不能证明现有输出契约与决定一致，保持C1或CPU。GPU产生的掩码、样本数、秩必须精确一致；浮点结果按既有契约检查，零附近的绝对误差规则须在试跑前明确，不事后放宽。存在不一致时保留异常工件、冻结受影响支持类别并用CPU整候选核算，不只盯最终IC是否靠近阈值。后续若将公式计算或月IC也搬GPU，属于新的支持范围，须另核分数排序/并列与门槛影响。

### 7. D：只有剩余热点支持时再做的优化

**公共表达式缓存。** 先从冻结AST清单统计重复节点及其求值耗时，缓存键含完整节点语义、所有窗口/常量、字段来源、轴/池及输入摘要；不能仅用抹掉参数的canonical模板。只缓存高收益节点，按字节限额并记录命中/淘汰。同一子表达式可复用不意味着相似候选等价，近似或同秩候选不能跳过。初始预算建议不超过512MiB，并受实际内存余量进一步约束。

**有界流水。** 在单候选路径通过后，可用一个CPU生产者准备下一因子，一个GPU消费者处理当前因子，队列最多2个因子。先测确实存在CPU/GPU空闲交替再做；有界队列、异常传播、按单元身份落库，不创建多个独立全池进程。CPU算子受GIL或内存带宽限制时不承诺线程翻倍。

**bootstrap与聚类。** 重新profile后才决定。不要关闭bootstrap、减少B=10000或换种子；如随机索引生成占比显著，可以另验证同种子同有效月数下的索引序列复用，但必须保持原抽样、浮点操作和输出契约。聚类不改阈值、不按代表淘汰，通过者增加后如出现二次复杂度热点再处理。

**暂不做。** 不建设全算子GPU框架，不GPU化L2资金竞争/撮合，不买云资源，不安装新驱动，不物化全部候选或完整`股票×日期×滚动窗口`张量，不重写整个引擎。

### 8. 资源预算与计时方法

5552×972×8约43.17MB，是一个float64字段的原始下界；六个前向收益面板即约259MB，未计因子、掩码、排序值、int64索引、临时区及框架缓存。8GB显存不支持随意同时加载92个字段及全部中间量。

- 初始GPU预算取`min(4GiB, 当前空闲显存×60%)`，一个worker；同时记录allocated/reserved和nvidia-smi占用，包含框架/桌面预留。
- 主机按RSS和系统可用内存控制队列/缓存，建议保留至少2GiB可用余量；不足时先释放缓存/减小在途批，不通过减证券数改变正式研究。发生持续换页时该轮计时标资源污染，结束自己的基准，不停止其他任务。
- 对比三条路径：冻结CPU、B阶段优化CPU、B＋GPU。统一当前清单代表、全股票池、同输入内容、同输出职责、同线程预算；冷装载单列，复用bundle暖态3轮取中位和范围，GPU测量包含显式同步、上传/回传与CPU回核。
- 分别记录输入验证、装载/PIT、公式、矩阵转换、月IC、bootstrap、衰减、聚类、序列化、恢复扫描及总wall。GPU初始化不藏在暖态结果外：另列冷启动总wall。
- 真实代表最多20个，按算子/字段/嵌套/窗口机械选，不看收益；若旧20个不属于当前1430清单，按同一预先固定规则重新选并记录。重复测量计技术重跑，不新增假设。全量1430未跑时只给分层加权估计，含装载/回核/落盘，不宣称全批实测或可靠上下界。
