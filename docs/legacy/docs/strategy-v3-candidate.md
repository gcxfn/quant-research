# ETF 轮动 V3 候选优化（未上线）

## 结论

当前 V2 的主要问题不是“0.5/0.3/0.2 权重不够好”，而是两个结构风险：

1. **Top1 单押**：一个主题 ETF 满仓，组合波动与回撤过高；
2. **直接相加原始收益率**：高波动主题的绝对涨幅天然更大，容易长期挤占排名前列。

因此 V3 候选不做参数网格搜索，只做两处结构改动：

- 对 R20、R60、R120 分别做当月合格池的横截面百分位排名；
- 三个排名等权平均，不再使用 0.5/0.3/0.2 的绝对收益幅度；
- 每月持有 Top 3，目标等权约 1/3；已有入选仓位不做无意义的月月精确再平衡，降低换手；
- 趋势门禁、历史长度、流动性门槛、月末信号、下一交易日开盘执行、交易成本保持不变。

## 不建议加入的改动

- **2ATR/3ATR 机械日频止损**：在本样本的探索实验中明显破坏趋势收益，不应直接塞入生产回测。
- **沪深300择时过滤 / 市场宽度阈值**：全样本可能更好，但验证段并不稳定，容易成为新的过拟合来源。
- **继续微调 20/60/120 权重**：样本只有约 5 年，权重搜索的自由度相对样本过高。

## 必修的工程问题

1. 原包文档说“止损纳入正式回测”，但 `run_rotation()` 实际没有日频止损逻辑。本优化包已把口径改为：**正式 V2/V3 候选回测均不含日频止损**，止损属于持仓执行层。
2. 原包 `plan.py` 的止损检查用“当天 close - 2*ATR”与同一个当天 close 比较，ATR>0 时无法触发。本优化包已改成**持仓以来最高收盘价 - 2×ATR** 的高水位跟踪止损。
3. 原包 `buy_max_lots()` 在仓位估算中会重复叠加一次滑点。本优化包已修复，并增加回归测试。
4. 数据清洗层现在会在数据源提供 `amount` 时保留显式成交额，流动性门禁优先使用 `amount`，旧缓存仍兼容。
5. 当前策略正式版本字段仍为 `v2.1.0`，而工程 CHANGELOG 已到 v2.4.x；建议后续区分 `strategy_version` 与 `app_version`。

## 上线门槛

V3 现在只应作为候选。建议从下一交易月开始记录 V2 与 V3 的并行纸面信号，至少积累 6–12 个月前向样本。核心观察：

- V3 是否继续降低最大回撤与单月尾部损失；
- Top3 的额外交易成本是否仍可接受；
- V3 与 V2 的相对优势是否不是由少数月份贡献；
- 真实成交滑点与最低佣金是否显著偏离当前假设。
