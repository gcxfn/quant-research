# 个人量化系统分层审查计划

日期：2026-09-10。状态：按用户“你出计划”编制；本次交付为计划，不代表审查已完成或任何运行门禁已解锁。

## 1. 目标与边界

目标：确认从时点数据到因子、统计判定、组合账本及用户输出的关键链路是否可信，识别历史结果受影响范围，并给出保留、修复或替换组件的依据。

当前开发主线仍为个股多因子月频 Top15 产品；生产 V3 ETF 月频轮动与做T辅助边界不变。本计划不改选股规则、交易结构、费用协议、研究窗口、统计阈值或收益目标，不连接券商。不得借审查重新搜索已封存家族的参数。

审查覆盖全系统的关键依赖与入口；逐行深审优先覆盖会改变研究判定、资金或可执行标识的模块。旧研究脚本仅在被当前链路调用或被缺陷追溯命中时展开；界面美化、打包与无关重构不在本轮范围。

依据：AGENTS.md、各轮有效预登记与决策记录，以及 numpy 双路径两轮独立审核。启动时重新核验最新修复与在途批次，不把文档中的旧 PID、旧测试数当作当前状态。

## 2. 执行纪律和分工

- 沿用现行分工：主对话负责协调、打包与记录；实现由既定实现角色承担；Codex 独立审核计划、修复代码和工件。实现者不能自行签发最终 PASS。角色或模型不可用时明确报告，不把同一实现的自测改称独立审核。
- 阶段先做只读定位和独立反例；确认缺陷后形成有边界的修复包。实现与审查分开，不在审查过程中顺手改策略。
- 在独立目录固定受审代码与配置。记录受审文件内容身份、数据清单、Python/numpy 版本、实际计算路径及回落原因；检查受审期间是否漂移。不得清理他人的脏工作树或覆盖在途进程依赖。
- 离线必跑测试保持零第三方依赖；可选库只在隔离环境做对照。对照引入的依赖限制调整、正式组件替换须形成具体变更方案，不能因本计划直接改变工程纪律。
- 科学定义与既有实现冲突时分别记录“兼容性”和“数学正确性”。例如常数序列产生非零 ZSCORE：复刻旧行为不算科学正确性闭合；改变语义要记录协议修订和工件影响，不能静默修正后沿用旧 PASS。

## 3. 阶段、检查内容和验收

按 A→B→C→D→E 推进。B/C 通过是攒批留出窗考试的审查前置条件；D 通过是新组合精测及产品可执行资格所需条件之一，不替代原有门禁。

| 阶段 | 范围与动作 | 独立验收证据 | 完成条件 |
|---|---|---|---|
| A：固定现状、先审检查器 | 列出当前入口、调用关系、有效预登记、批次与历史 PASS；核对 numpy 最新修复；检查差分、确定性、身份和报告检查器 | 对检查器注入排名换位、None/值翻转、bootstrap 1ulp 差异、计数变化、缺单元、重复 ID、空工件、错误退出码 | 应拒绝的负例全部拒绝；报告 PASS 与进程退出码一致；numpy 遗留审核项闭合 |
| B：数据与因子 | quant/history.py、validation.py；factor_miner/data_fields.py、compiler.py、operators.py、operators_np.py；当前财务/PV1实际装载依赖 | 手算小样本、Decimal/Fraction 参考、时间截断和排列性质测试、TRAIN 边界样本 | 时点和掩码违规为零；数学定义与实现的差异全部裁决；两路径离散输出无未解释分歧 |
| C：统计、筛选与留出窗控制 | stats.py、stats_np.py、event_stats.py、partition.py、validator.py、registry.py、director.py 及当前财务/PV1对应门禁 | 小样本秩/区间复算，固定重采样索引独立计算，阈值两侧反例，阶段越权/漂移/重复使用的失败测试 | 候选数与修正口径一致；门禁和计数精确；bootstrap 按冻结口径核验；未授权读取及身份漂移 fail-closed |
| D：成交、资金与输出 | quant/execution.py、market.py、backtest.py、account.py、positions.py、t0.py；factor_miner/backtest.py 及新组合实际入口 | 人工逐笔账本，价格/股数/费用/现金/净值逐项对账；一个组合端到端 smoke 和一个做T场景 | 无前视成交、非法可卖量、漏费或共享资金超配；现金持仓守恒；输出门禁与内部状态一致 |
| E：历史影响与组件取舍 | 从缺陷触发条件追溯实际调用、批次、候选和下游消费；评估高维护成本标准组件 | 影响矩阵、必要重跑清单、同输入组件比较、最终审查报告 | 每个缺陷都有闭合证据或明确阻断；每批结果都有可追溯状态，不能用泛化 PASS 替代 |

### B 必查案例

1. 公告日、报告期和实际可用时点分开；同公告日重复/冲突行顺序确定；字段缺失、源滞后、无权限不被填成零。数据发布时间若无充分证据则保留不确定性，不把日期字段自动等同于盘前可得。
2. t 日信号只依赖 ≤t 的允许数据；改动 t 之后记录不应改变此前因子和资格。全日历缺行占位，不压缩持有期；ST、停牌、上市时长、流动性严格按冻结时点判断。
3. 在市/退市来源、复权价格和实际成交价分开；公司行为不能重复入账；行业快照缺口仍封顶探索级。
4. 全窗/部分窗、None/NaN/±inf、常数小数、近零方差、消减误差、极大/极小有限数、零分母、并列排名和稀疏覆盖；每类不仅测单算子，还测 ZSCORE→排名/IF/SIGN 的传播。
5. 股票字典顺序、PYTHONHASHSEED、缓存开关和清理不应改变结果；测试实际启用 numpy 而非静默回落。Python 版本变化可能改变 sum 的算法，运行版本必须纳入证据。

### C 必查案例

1. Spearman 并列与缺失配对；月末、前向收益、未成熟标签和现金日口径；均值、分母与报告计数一致。
2. bootstrap 的块构造、日期顺序、月数不足、随机种子、随机消费次序、分位数公式；固定输入严格复算和全链输出核验分开。
3. 多重检验以各预登记实际冻结的候选数/家族数/阶段为准，列出公式与代码定位；不能用一个统一 α 覆盖不同协议。
4. 重复公式、窗口扫描与正式基准单元的计数；失败及 lineage 完整保存；EXPLORATORY_ONLY 无晋级通路。
5. TRAIN/VALIDATION/LOCKBOX 真实入口的访问限制、候选身份、并发或重复调用、崩溃后状态、恢复/续跑不混批。失败或中断的锁箱访问也留痕，不自行重置一次性预算。

### D 必查案例

1. 同日新买不可卖、已有底仓可卖；零现金反T、未完成 open_t 的延续、部分成交和手数限制。
2. 买卖方向封板、无量、停牌、涨跌停价取整、止盈止损同 bar 歧义、退出受阻顺延；信号生成与成交时间严格分开。
3. 最低佣金临界点、买卖费用差异、逐笔费用、费用后保本价；费率以有效配置和已确认协议为准，发现规则依据过期再查官方来源。
4. 多标的争用现金、先卖后买顺序、仓位上限、补仓与分档卖出；净值=现金+持仓估值+已建模应收项，费用和分红只入账一次。
5. 收益年化、夏普、最大回撤和未平仓估值独立复算；收益表现好坏不影响工程验收。
6. CLI/报告中的生成时间、数据时点、版本、成本、研究/可执行状态与账户输入一致；数据过期、门禁未过、无底仓时必须正确降级。

## 4. 验证方法与证据规则

- 三类证据组合：可手算的预期答案、数学/时间/账本不变量、独立实现或成熟组件对照。两条路径共享同一错误定义时，差分通过不足以验收。
- 离散值（门禁、可卖数量、身份、计数、缺失模式、订单方向）精确比较；金额按已定义币种精度和费用取整规则；连续统计值按对应冻结协议。不能在看见差异后临时放宽容差。
- 对同路径确定性与 bootstrap 严格要求单设比较器，不复用宽容差检查；检查器自身须有能稳定失败的负例。
- 每个重要缺陷给出触发条件、最小反例、预期/实际、代码定位、影响范围、修复提交、独立复核和重跑要求。
- 修复后先跑相关单测及必要端到端 smoke；一组相关修复完成后跑一次全仓离线测试。只有新变更、失败或未解风险才扩大或重复验证，不以测试总数代替覆盖说明。
- 合成数据先行，真实对照仅使用事前固定的 TRAIN 样本。样本按风险覆盖选定并留档，不按收益好坏挑选；规模扩大由前一级正确性和资源实测决定。

## 5. 在途运行和重跑决策

| 情况 | 处理 |
|---|---|
| 批次已终止，用户明确暂停重启（2026-09-10 用户补充的 R0 现状） | 维持停止；A 阶段闭合与 numpy 审核裁决后，给出引擎选择、受审提交/运行环境/数据身份、新目录、资源与对照方案，再由用户决定恢复。单项 PASS、旧 REAL_RUN_UNLOCKED=True 或历史启动授权不构成此次恢复授权；残缺旧批不能当完整全量对照 |
| 已批准纯 Python TRAIN 在途，尚无证据命中本轮缺陷 | 可继续；不干预进程；完成工件仍按原规则送审 |
| 缺陷确认影响某因子或批次的数学输出/门禁 | 标记该范围“待复核，不可用于晋级”；保留原工件；修复后从最早受影响节点重算 |
| 仅报告显示错误，底层数值核对正确 | 修正报告并记录，不做无意义全量重算 |
| 通用统计或账本缺陷，暂不能界定影响 | 阻断依赖该模块的判定，先追踪触发覆盖；不得默认所有历史均有效或全部作废 |
| 已观察 VALIDATION/LOCKBOX 被确认需重算 | 不擅自读取或重考；先给出缺陷、受影响候选、重跑范围和污染披露，由用户按原纪律决定例外；原访问记录永久保留 |

任何重跑使用新目录、新代码/数据身份，禁止覆盖原结果或把跨身份缓存混用。先完成正确性小样本验收再跑全市场；纯/加速大批顺序运行，避免已知内存竞争。计划本身不启动监控、后台进程或自动化。

## 6. 成熟组件评估：只对明确模块做有界比较

初步候选方向为因子计算标准算子、组合回测和绩效统计；vectorbt/Qlib 等仅列为待评估对象，不在本计划宣布适用或决定安装。执行评估时查官方接口、维护状态、许可证和版本，再选最多两个候选。

保留同一份冻结因子值/订单输入，尽量不重写假设。与人工小账本、现有模块对比成交、费用、现金、持仓、净值和指标；只比较总收益方向不算通过。明确默认行为、必须自定义的规则、无法支持的边界与适配代码量。

满足正确性后再测同机冷/热启动耗时、峰值内存、依赖负担和维护工作量。结果允许三种：保留自研、用成熟组件替换一个模块、暂缓。独立对照可保留用于回归，但不是成熟组件唯一允许的角色。不为了已经投入的代码保留自研，也不为了框架名气整体迁移。
