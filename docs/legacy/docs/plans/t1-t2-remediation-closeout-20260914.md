## 3. S1：审核器失败时必须阻止通过

当前 `experiments/ten_year_minute_accounts_review_20260913.py` 虽已计算source_review_ok、patch_manifest_ok、archives_ok，却没有将这三个false统一转成失败；非WAITING_REVIEW路径被记error后continue。其文档“任何一层失败都会抛出”因此仍宽于代码。当前第14批保存值均为true，本项是公共门禁缺陷，不据此声称旧数据已污染。

最小修复：

1. 复用现有输入与账本核验，补统一必需条件：审核/补丁/档案摘要通过，路径ID恰为冻结四项且不重不漏，四路径具有可审核终态与完整账户。若仍支持部分批检查，明确输出“仅部分检查”，不得产整体PASS。
2. 小夹具验证：正确完整批成功；至少一个必需摘要false失败；缺/重复路径和BLOCKED路径不能签整体通过。负例用临时副本或摘要夹具，不修改真实大ZIP或旧工件。
3. 用第14批冻结运行源码审核第14批；新审核器及其依赖单独绑定摘要。只修改审核工具不要求运行源码重新冻结或重跑账户，不把工具版本变化误认作账户输入漂移。
4. 实际复核1554证券输入、信号、补丁及源身份；已存在大型ZIP完整摘要证据先核身份/时间，若沿现有审核器复算只做一次，不在每个子检查重复扫包。任何复用证据须说明覆盖范围，不能冒充本轮亲算。
5. 逐日独立重建现金、持仓、可卖、净值，逐笔以独立费率规则重算费用；核四路径120个月、2431会话与日历一致。沿已验收数值容差，不因失败放宽阈值。

通过条件：正常批完整通过，已知门禁反例拒绝；所有四路径结果与独立核算一致。核算报错必须定位输入、实现或审核器原因，不能只改结果中的状态。

## 4. S2：分钟例外从日触价判断收窄到实际订单依赖

已修好的边界测试保留。本阶段处理的是另一个问题：日聚合低价有冲突时，证明“某天可以买到”不等于证明“每根bar成交量、时间、现金竞争和最低佣金不变”。当前允许price>minute_low或price>=首bar.open，尚不能单凭这两个条件宣称完整成交路径无影响。

### 必查实际依赖

- 从第14批每路径实际Provider记录、订单/成交/未成交记录取例外使用，不能复用第12批计数，也不能用选股上界代替订单。
- 至少覆盖曾命中的002442/2016-03-01、603026/2019-05-06；如新路径没有使用，记录“无依赖”。只有补丁存在但未消费的证券日不阻塞本批。
- 对每次使用记录：源与补丁摘要、日/分钟差异、限价/类型/激活时间、剩余股数、逐bar容量和共享参与量、实际部分成交、现金占用、最终未成交及费用。
- 对002442跨bar部分成交重点核验；对603378/2019-02-01卖出12.45而日低12.49的有界差异单独核已有披露和撮合来源，不擅自裁定日线或分钟谁错。

### 裁决顺序

1. 原始数据确可补齐或可凭已核来源澄清：新增原始/派生批及身份，再走同一Provider。不得用日低反填分钟。
2. 不需未知bar也能证明订单无依赖：把证明条件写成可检验门禁。例如严格低于真实日低的限价买入不触发；其他条件必须同时证明时点、可成交量、现金及共享容量。首bar开盘触价但未全额成交本身不构成证明。
3. 不能证明：关闭该项“无触发依赖”例外，阻断受影响订单路径并给出具体补数请求。不得改名成普通披露绕过原硬阻断，也不得扩大1%/5%线。
4. 如做敏感性分析，仅在事前冻结的有限假设下作影响诊断，单列合成数据、方法和运行次数；不得把假设分钟当正式执行证据，不能测到满意结果为止。

最小新增测试是一个“日级触价相同、逐bar剩余订单/容量不同，产生不同部分成交或费用”的反例，并验证新门禁拒绝这类未经证明的放行；既有7例继续保留。未知时点/量分配不能从日聚合量守恒反推，若真实证据不足就明确BLOCKED。

有界research_disclose仍沿现有授权处理。对603378不额外要求所有来源逐股对齐；核验成交确来自合法已审分钟、披露没有丢失、代码没有借tolerate_disclosed_minute跳过其他金融核算。不将1%价格差写成收益误差上界。

## 5. S3：核已有归因及剩余数据问题

### 已产出报告的独立复算

- 两身份×三个阶段，按标签月划分60/36/24月；核mean/median/标准差定义、有效IC数、正负月、覆盖和缺失分解。全期行与阶段行不能重复计数，不能平均三个阶段均值替代120月加权均值。
- 从实际账户机械重选两主路径各最差3个月、最差5只；与解释表一致。独立从成交、期初/期末持仓和事件核损益分解，不只引用生成器自身assert。
- 分清实际账面损益的加法项与重叠子集：“信号新进退出”“受数据问题影响证券”不再加一次。相对成交日收盘的价差注明是描述指标，不当作已识别的市场冲击或可实现机会成本。
- 核说明中的月初价格实际使用上月末还是当月首日；以账户收益的期初定义为准，若只是文字错仅改报告。缺报价不能补零使分解对平。
- 核新文件及生成脚本的身份链：归因附加文件若不在原报告manifest中，另加不可变附录清单绑定文件、源码、账户与原报告摘要，不改写旧manifest来掩盖追加时间。

### 剩余公司行为与T1取数范围

- 从第14批实际data-issues重新整理残余事件，不照搬旧数量；区分普通现金事件、送转/股份权益、未核价格跳变。002166、002776等仅在新批存在持仓依赖时处理。
- 有既存公告/裁定先复用；仍无法核准的，写明受影响持仓/日期及经济意义。未核送转或其他关键权益不可只因nav_valid=true就当作完整有效净值。需要修改数据或事件消费才进入S4。
- 红利税、退市清算等历史已披露范围不自动扩大为新产品功能；但“限制”不得用于掩盖已知能修的漏权益。关键持仓估值/权益缺口未解决，相关完整收益不得获准确性PASS。
- T1按原任务承诺列“本轮必需已交付”“具体受阻依赖”“未来扩展数据”；只对必需缺口追取，失败chunk按原限流续传。未授权要求所有宏观/行业/未来订单分钟齐全才收口。取数进程与研究读取窗口分开管理。

## 7. S5：验收与停止标准

审核新目录建议 `artifacts/t1-t2-remediation-review-20260914-N/`，启动时取未用编号。最低交付：身份与命令索引、四路径独立核算、分钟例外裁决表、阶段/归因复算、剩余限制及review.md；不在旧第14批覆盖verification.json。

| 裁决 | 条件 |
|---|---|
| PASS | 受审范围要求完整满足，无未解决的正确性缺陷；仅表示该范围验收 |
| PASS_WITH_LIMITATIONS | 必需交付完成、无影响受审正确性的开放缺陷；有明确、与用途相容的数据/模型限制，逐项披露 |
| CHANGES_REQUIRED | 仍有可修代码、输入消费或报告错误，指出文件/路径与最小修改 |
| BLOCKED | 具体必要外部数据/证据不足，受影响阶段无法完成；保留不受影响结果 |

分别裁决T1能力/支持与T2-A/B/C，不能“一张PASS覆盖所有任务”。受限通过且整体目标仍未完成时，执行状态不写DONE。统计UNKNOWN、晋级BLOCK、不可执行研究状态、2025+/生产冻结保留；十年修正结果不删除2023–2024历史失败结论。

通过后在四份任务书末尾追加同一时间/证据路径的最终状态，纠正旧状态与新交付不同步，不删除历史记录。阶段性测试通过不等于正式最终签发。

停止条件：正常路径、原缺陷回归、关键负例及一次独立核算充分覆盖后即裁决；无具体新反例不增加第三层审计。若分钟证据不足，交付具体BLOCKED结论和补数条件，不反复重测同一缺口。
