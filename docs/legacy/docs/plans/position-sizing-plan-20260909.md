# 仓位分级计划：策略仓位上限（2026-09-09）

**状态：已作废（2026-09-09）。用户随后澄清"说错了，是做1"——选择改规则路线，仓位分级不执行。本文件仅留档。**

## 1. 决策与性质

- 用户选择"少放钱"路线：给 V3 月频ETF策略设**仓位上限**，只把账户资金的一部分交给策略，其余留现金。
- **这是资金分配决策，不是策略规则变更**：不改排名、门禁、Top3、费用任何一条规则，因此不需要预登记、不需要样本外验证。它只是把 R3 已测出的收益/回撤按仓位同比例缩小。
- 要明说的一句话：仓位分级**不改善策略质量**（夏普仍是0.46），只是把"赚多少/亏多少"的刻度整体调小。它治不了本，治本要靠第1条路线（改规则，须重新预登记验证）。

## 2. 档位表（基于 R3 实测的线性缩放，是粗略换算不是预测）

以10万元账户为例，历史 R3 口径（年化+10.19%、最大回撤−58.85%）按仓位比例缩放：

| 策略仓位 | 投入金额 | 预期年化（粗算） | 历史最大回撤同比例 |
|---:|---:|---:|---:|
| 满仓 100% | 10万 | ≈10.2% | ≈−59%（−5.9万） |
| 1/2 | 5万 | ≈5.1% | ≈−29%（−2.9万，占总账户） |
| **1/3（推荐）** | **约3.3万** | **≈3.4%** | **≈−20%（−2万，占总账户）** |

- 推荐1/3的理由：正好落在用户确认的约20%账户回撤预算内。
- 档位只是一个配置值，随时可改，改档位不需要任何验证。
- 缩放的局限：手数取整（100份整手）会让小仓位实际偏离理论比例，高价ETF更明显；线性缩放不含现金利息（口径无风险利率=0）。

## 3. 执行口径

1. **仓位上限定义**：策略仓位上限 = 账户总权益 × 仓位比例（配置项，默认1/3）。每月末信号日照常生成 Top3 信号，但订单金额按上限计算，Top3在上限内等权。
2. **上限随账户浮动**：每月信号日按当时总权益重算一次上限；月内不调整。
3. **剩余现金**：不进入任何策略建议，不做自动划转、不做理财建议，就是躺着。
4. **做T口径同步**：`t0` 计算可用现金时以策略仓位内的现金为准，看不到上限外的钱——防止做T建议变相突破仓位上限。做T其余规则（可卖底仓、费用后保本、T+1）不变。
5. **人工执行不变**：所有订单人工录入，系统只输出建议；建议输出须标注仓位比例假设。
6. **做T/信号的数据门禁、失效规则全部不变。**

## 4. 工程改动点（实现交子代理，主对话审核）

1. 配置新增仓位比例项（如 `portfolio.position_scale`，默认1.0不改变现有行为；本轮生产配置设为1/3待用户确认档位后填入）。
2. `plan`/`signal` 的头寸计算处乘上该比例（含Top3等权后的每标的金额与手数取整）；`t0` 可用现金口径同步。
3. 单测：比例缩放后的金额/手数/费用后保本计算；比例为1.0时与现有结果完全一致（回归保护）；t0 现金口径用例。
4. 端到端 smoke 照旧必须通过；全量单测必须通过。
5. 不改 `quant/` 中任何策略规则代码；改动限于头寸计算与配置读取。
