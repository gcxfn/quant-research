## 1. 审阅结论与证据

原方案方向可探索，但不能按原“3–4周完整GPU引擎、必达1小时”直接立项。发现以下问题：

| 等级 | 原问题 | 修订 |
|---|---|---|
| P1 | 约30秒被写作单元求值时间，未拆统计/成本/聚类 | 先剖析完整调用链，不能凭总耗时认定FLOPs或内存瓶颈 |
| P1 | 1482/2000与17小时混用 | 用最新冻结清单及源码摘要重算；本次看到-3为1456行，wave3仍在检查，不能混批计时 |
| P1 | TS_RANK误写为并列平均秩 | 实际为窗口内≤当前值的占比；与CS_RANK平均秩分开 |
| P1 | 统一1e-9容差和门槛附近回核可能漏掉排序变化 | 保留既有数值契约，检查掩码、秩、选择及门槛决定；不能只看最终IC靠不靠近门槛 |
| P1 | 缺分片完整性检查，汇总n_tests可能按已完成子集缩小 | 固定全清单身份和预期槽位，缺片只报进度，不能生成正式汇总裁决 |
| P2 | 把26“组字段”直接当26张矩阵，推断总内存降至1/4 | 实际计字段数、峰值副本和临时空间；现登记称92个字段类，须以真实bundle键为准 |
| P2 | CPU云机1–2小时、零改动零复核无实测支持 | 改成另行资源选择，先做受控并发试验，不自动购买或上传 |
| P2 | 强制镜像3000行测试和2–4轮复审 | 复用参数化语义用例，只测变更、关键负例和一次独立核算 |
| P2 | GPU未达1小时后“停止”与“转分钟专用”矛盾 | 统一决策：有效CPU改进可交付；GPU收益不足则停止该分支，不自动扩大场景 |

本次只读检查的事实：

- 本机nvidia-smi：RTX 4060 Laptop GPU，8188MiB显存，采样时可用6771MiB，驱动592.00；系统内存16780566528字节。可用显存随桌面和其他进程变化，不作永久保证。Win32_VideoController的AdapterRAM显示值不能替代nvidia-smi。
- 旧trial20实际工件：`artifacts/new-factor-research-20260912-2/trial20-run/`，20/20已完成；约13分钟装载与约11分钟计算是任务记录中的时间拆分，不是本次profiler证据。
- 当前任务板登记-3为1456行；本次进程快照显示-3 trial20及秩等价检查在运行。未停止它们，未在其运行期间更换引擎或抢跑全池基准。
- `experiments/t3_l0_batch_20260913.py`每片启动一个新的director进程；这会重复构建bundle。假设20片每片13分钟，装载项约260分钟；一次构建后复用的理论节省约247分钟，必须用实际分片数和计时确认。

- `stats_np._average_ranks_np`仍有逐排名游程的Python循环；`ic_decay_curve_np`每候选重建因子/收盘/掩码矩阵并逐期限逐日调用Spearman。模块旧注释称统计为大头，仅能作为定位线索。
- `director.train_test`包含公式、月IC、bootstrap、逐日衰减和分层；`evaluate_units`在成本阶梯开启时还会再次求值并跑旧成本梯度。实际命令是否开启须核运行元数据，不把这整段都叫NumPy算子耗时。

## 2. 目标与本轮不变项

- 优先减少重复装载、Python排名循环、重复求值及可避免的数据转换，再决定GPU是否值得做。
- 维持当前冻结的因子公式、方向、窗口、PIT、全量达标晋级规则、标签、统计输出及未校准状态。不能用关闭bootstrap、改随机数、减少衰减日期或放宽阈值冒充等价提速。
- T3目前任务记录为先做L0；如实际pipeline仍运行旧成本阶梯，先核登记依赖，单独记录L0-only执行配置修订并证明L0输出等价，不直接改旧入口默认。
- 不纳入L2路径依赖撮合GPU化、实时分钟因子、10k新构造扩矿、前后端或新数据窗口。它们需要另立具体目标。
- 纯Python是语义参照，当前冻结NumPy是性能和已运行结果参照。保留两条旧路径；GPU不得成为强制依赖。
- 当前正在执行的T3保持冻结身份。优化在隔离开发环境验证；本轮余下候选是否换优化路径，以完成验证后的新快照和明确切换记录决定，不在运行中热改。不能承诺GPU必用于本轮，也不把“本轮永远不用”作为技术前提。

## 3. P0：先定位端到端瓶颈

交付`profile.json`和`baseline.md`，至少分离：

1. 数据读取、PIT/资格处理、bundle构建及字段数组转换。
2. 公式编译与求值、CS_RANK/滚动算子、出口list转换。
3. 月IC、逐日衰减、分层、bootstrap。
4. 可选旧成本阶梯、重复公式求值、相关聚类、JSON/摘要落盘。
5. 分片启动/装载次数、峰值RSS、交换分页、GPU传输及显存（仅GPU阶段）。

固定样本从已登记候选按算子/嵌套/窗口/字段分层机械选最多20个，兼顾简单公式、CS_RANK嵌套、CORR及TS_RANK，不按收益选。首片性能评估属于同候选技术验证，不生成新假设。

先用小面板做调用计数和cProfile，再在无人争抢资源的时段做一次全池冷装载及3次同bundle暖评估，报告中位数和范围。登记CPU/GPU/依赖版本、字段数量、日期/证券轴、代码与数据摘要、候选ID、实际backend、是否启用成本阶梯。

不要在16GB机器上同时启动多个5GB全池进程。先单worker，实测留足内存后再测2 workers；Windows启动子进程不假设继承共享Python对象。

估算用真实公式类型的分层耗时及冻结清单频数，报告装载/计算/统计/I/O分别的总量。若热点占比为p，即使该段无限快，整批加速上界也只有1/(1-p)；单GPU算子倍数不能直接外推整批。

## 4. P1：先交付小范围CPU优化

按P0确认的热点依次实施，某项非热点则不做：

1. **装载复用与可靠检查点。** 一个长寿命worker加载一次bundle、顺序消费多个逻辑分片，单元结果完成即写独占文件并原子完成标记；恢复时验证候选/代码/数据/统计协议摘要。若现有公开入口不支持传入bundle，抽出最小执行入口，保留旧pipeline行为，不重写director。
2. **统计排名向量化。** 首查`stats_np._average_ranks_np`游程循环，借鉴既有向量化排名实现，但不能直接套CS_RANK的有限值掩码：统计Spearman当前只剔None/NaN，±inf参与排名，两个契约不同。保留平均秩及既有累加顺序，复用纯/NumPy对照测试。
3. **静态面板缓存。** 同一只读bundle/轴/预热/池掩码身份下，复用收盘、掩码及有限数量的前向收益矩阵；不得跨不同成对有效掩码直接复用标签秩。因子临时数组按单元释放，不存全体构造的全日面板。
4. **去重复计算。** 若成本阶段需要同一因子序列，显式传递已算值；确认L0-only配置后只跳过非本轮义务的成本工作。保留全部已冻结统计输出。
5. **列式数据按需推进。** 先采用内部只读array缓存或必要字段的磁盘数组缓存，不强制改所有StockRows/公共bundle接口。只有profile证实装盒数据仍限制吞吐，才做字段级mmap/流式构建，原接口用明确适配；避免同时持有完整dict/list和重复数组声称省内存。

内存估算只报原始面板下界：5552×1000×8约44.4MB/字段；26字段约1.15GB，92字段约4.09GB，均未含Python对象、掩码、排序索引、前向矩阵、缓存和输出。字段组数不等于字段数。矩阵化不自动加速CSV解析/PIT。

**检查点正确性前置修复：** 现批跑器只见batch_status.json就跳过、部分片缺失时aggregate继续并以len(rows)为n_tests。优化入口须以冻结全清单的预期槽位去重核对，核终态与结果摘要；缺/重/错身份只产进度及问题表，不产正式全批gate。现有统计口径未经校准仍如实披露；性能任务不擅自修订统计方法。

## 5. P2：有测量依据后做本地GPU最小原型

进入条件：P1完成后仍有明显热点，且该热点可在GPU上批量计算。优先选择实测耗时最高的一种排名/统计或滚动路径，不同时实现15个算子加统计全家桶。

- 默认先选CuPy，因现有NumPy数组路径最接近；只装在隔离环境，安装前检查该Python/CUDA组合的官方支持。若不兼容，记录阻塞再决定PyTorch，不维护两种GPU框架。不得为了安装自动改系统驱动或购买云资源。
- 先用float64真实面板形状测试，不用FP32/Tensor Core宣传值推断速度；本地消费级卡的实际双精度速度由微基准确认。
- 两种候选路径由P0决定：CPU公式→一次上传→GPU批量统计→小结果回传；或者支持的完整公式子树常驻GPU求值。不能每股票、每算子来回搬list。
- 仅上传当前公式/小批公式的必要字段；共享close/掩码有身份缓存。一个GPU worker。显存分配预算初始取min(4GiB, 采样空闲显存的60%)，预留驱动/桌面/排序工作区；按实测减小块，不更改有效样本。
- 禁止直接物化整个[S,D,W]窗口。S=5552、D≈1000、W=120时单个float64窗口体约5.3GB，多个临时量会超8GB显存；分股票/日期块执行。滚动时间块需保留嵌套AST所需完整halo，CS_RANK需保留同日完整定义截面，不能按股票块各自排名。
- 不直接用前缀和差或E[x²]-E[x]²替代既有两遍方差算法；高偏置/近常数可产生消减误差。若采用新算法须单列误差证据和回核策略。
- GPU计时包括同步、传输、初始化/JIT、缓存、统计、回核及落盘；同时给冷启动和暖态结果。不得只用异步CPU计时宣称GPU提速。
- 最小新增选择接口为显式backend（pure/numpy/cupy），只在新入口接线；不改旧环境变量默认语义。记录requested_backend、actual_backend和回退原因，显式请求GPU时不静默冒充成功；未支持公式预先路由冻结NumPy，不在算子间随意混算。OOM可有限缩块，仍失败则记录并整候选回CPU。

## 6. 语义与等价性：修正原计划错误

| 对象 | 必须保持的实际语义 |
|---|---|
| TS_RANK | count(window_value≤current)/n，含自身；不是平均秩。[1,2,2]末值为1 |
| CS_RANK | 有限值参与，平均秩/有效数。[1,2,2]为[1/3,5/6,5/6] |
| Spearman | 现统计函数剔None/NaN，±inf保留；与CS_RANK有限掩码不同 |
| 缺失/inf | 全窗有效；ABS/负号/IF所选臂保留原透传行为；IF条件本身非有限则缺失 |
| STD/ZSCORE/CORR | 样本方差ddof=1，严格常数窗输出缺失；近常数按已有两遍式语义 |
| RET/DELTA/LOG/除法 | 原偏移、越界、非正LOG及除零规则不变 |
| 轴与字段 | close轴锚、常量广播、缺PRICE拒绝、稀疏字段缺证券全缺失、不截短或补造数据 |
| PIT/标签 | 原股票/日期顺序、预热、池掩码、标签成熟、2025禁读保持 |

确定性不等于跨CPU/GPU逐位一致。GPU后端float64、不启用fast-math/混合精度；同硬件/版本/配置重复结果需可复现，实际归约算法和块大小入身份。不能声称一个deterministic开关保证所有平台同值。

**验收分三层：**

1. 掩码、日期/证券身份、有效数、计数、排名及并列处理在同一数值输入上精确一致；有限浮点误差沿现有算子登记契约（现NumPy文档为1e-12相对），零附近另登记绝对界，不擅自放宽至统一1e-9。近常数、极大偏置、±inf、负零、全缺失、边界窗口须覆盖。
2. 组合公式的小数差可能改变排序，即使月IC远离门槛也要检查。核月末分数次序/并列组、有效样本、月IC序列及方向；对排序不确定、误差超界或门槛决定分歧的候选，用冻结CPU整候选重算，以CPU为准并保留差异。不能仅以距0.02或CI零点1e-6作为唯一触发条件。无法建立可靠歧义检测的GPU公式类别暂不获正式使用资格。
3. bootstrap仍在冻结CPU实现，种子、随机消费、全清单n_tests和数据顺序保持。报告CPU回核数量及耗时。保留统计UNKNOWN/未校准状态；数值等价不意味着旧统计门槛科学有效。

先复用现有测试数据和断言，增加后端参数/适配；不复制3000行测试。合成反例覆盖所有新支持操作及跨块/缓存身份，再做同全池最多20个机制/算子代表和门槛/排序异常例。只审核已实现支持集，未支持自动明确走NumPy。审查一次加具体缺陷复核，无固定2–4轮指标。

## 7. 性能决策、交付及切换

| 阶段 | 交付 | 继续/停止条件 |
|---|---|---|
| P0 | 分段profile、最新冻结清单的冷/暖基线与总耗时估计 | 没有热点证据，不建设完整GPU引擎 |
| P1 | 最小CPU差量、检查点/计数修复、数值对照、峰值内存及耗时 | 正确且实测节省则交付；CPU已满足需要可停止GPU扩展 |
| P2 | 一个GPU热点原型、支持集、传输/同步/显存与回核统计 | 同面板3次暖态中位数，目标相对P1热点至少2倍且代表端到端至少1.5倍；未达则停该分支，不强行转分钟场景 |
| P3 | 被接受支持集的有限接线、回退、复核及独立审核 | 决策输出等价、无数据缩减、含CPU回核后仍有收益才允许新快照使用 |

倍数是开发取舍门槛，不是速度承诺。首个开发时间盒为：P0最多1工作日、P1最多2工作日、P2最多2工作日；到点交付证据和未决项，不自动扩成数周工程。是否需要后续扩支持集由结果决定，不能按代码行数估工。

“全批≤1小时”保留为期望目标，使用最新冻结清单及完整协议实测判断；没有完整批证据只能给分层推算范围。未达1小时不丢弃已证实有用的CPU改进。比较对象须是同硬件同输入同职责的优化CPU，另列原CPU，不用昂贵云GPU对旧本机CPU制造倍数。
