- 性能隔离试验可与T1/T2不冲突的整改并行；涉及证券生命周期、池掩码等性能输入的修复必须先纳入基线。公司行为/分钟整改不要求阻塞所有独立装载和统计试验，但受影响账户不获放行。
- 新性能路径正式切换须同时满足自身验收和最新T1/T2审核要求。单次性能试验通过不自动恢复T3全量、L1/L2或生产。

- 使用本地已装NumPy/PyTorch，先复用已有GPU原型；不同时维护CuPy第二实现、不改系统驱动、不购买云资源。
- 不清理他人变更，不覆盖原始数据或旧包，不自动提交。窗口沿被冻结TRAIN及必要预热，收益标签不跨训练边界；2025以后行情收益不进入试验。

## 四、P0/P1：一次固定、有限的试验

### 1. 样本与计数

1. 使用启动时已审的真实股票全集，当前历史记录为5552只。完整保留其资格、缺失和历史身份规则；“请求5552”和“实际服务数量”分别报告，不筛去难算或缺字段证券以提速。
2. 从实际已冻结清单中按字段类型、滚动长度、排名/相关、嵌套深度机械选最多20个代表公式；具体ID和选择脚本在首次新数值输出前冻结。不按收益或门槛结果选择，不补造新公式凑20个。
3. 试验沿原TRAIN窗口和所需预热，不为了测速读新留出标签。为公平比较，CPU/GPU完全相同的股票轴、日期轴、池掩码、字段、公式、标签、种子和统计输出。
4. 这是性能技术重算：不新增研究假设、不产生正式通过名单。正式搜索分母沿已审清单身份记录，不能以20替代；测试次数、公式数、后端数分别计数。历史1430仅是旧快照分母，启动时不得未经核实硬编码。

### 2. 测量方式

- 小型合成夹具先验证实现；随后完整股票截面上做一次进程冷启动与至少3次暖态计时，CPU/GPU交替次序。正确性比较可复用这些产物，不再平行起第三套同负载。
- “进程冷启动”包括装载/转换/初始化，注明操作系统文件缓存是否可能已暖；不清系统缓存、不停他人进程。首次数组缓存构建与后续命中分别计时。
- 暖态是同已验证bundle内连续计算完整代表集；另报一次完整流程wall，包含身份核验、传输、GPU同步、必要回核、输出及收尾。CUDA用同步或事件计时，不能测异步发射时间。
- 记录CPU线程数、实际后端、PyTorch/NumPy/CUDA版本、电源模式、显存、峰值RSS、系统可用内存、后台负载、候选吞吐。严重资源争抢的测量登记无效，等合适时段再做，不据此改参数。
- 不同时运行多份全池数据包。若出现OOM、持续换页或系统可用内存低于约2GiB，停止该配置并记录，改为单候选/分块；不能缩股票全集后仍写全池结果。
- 最后按冻结公式类别频数估计全批时间，分别列一次装载项与重复计算项，标明未测类别和估计范围。推算不冒充实际全量跑完。

## 五、P2：CPU优化次序

### A. 必要字段的只读数组缓存，第一优先

保留原CSV/ZIP，利用已有装载逻辑生成日期隔离后的数值数组、缺失掩码及轴；优先复用NumPy `.npy` 和只读mmap。只缓存所选公式真正需要的字段，不重新建设全库格式，不在内存同时长期保留完整字典数据和重复数组。

缓存键包含消费源集合及内容摘要、预处理源码/版本、股票和日期轴、窗口/预热、字段单位、复权语义、池掩码及dtype。新缓存写临时目标，完整校验后原子发布；半成品不能命中。源变化、轴变化或规则变化必须失效。外部数据启动/恢复/收尾内容校验保留，不能用mtime或文件数代替。

在不可变且已验证的内部bundle生命周期内可复用其摘要；外部preloaded入口仍须验证。摘要扫描若成为热点，先登记其耗时再优化内部重复调用，不删安全门。

### B. 数组直接传入统计，按热点决定

若P1表明list/dict转换、重复构建面板占计算时间显著比例，保持公式输出为array直到统计结束，只在持久化边界转换。先接一个公共出口及其调用者，保留纯Python语义参照。若转换占比很小，本项暂缓。

### C. 有容量上限的公共表达式复用，最后考虑

只有发现多个已冻结公式确有昂贵公共子表达式时，按规范AST、输入与掩码身份复用。限制缓存字节数，超限逐候选释放，不存下全部候选全日面板；不同有效掩码不得共用标签秩。先验证复用次数和节省，不引入通用计算图框架或多进程池。

CPU每项以同一基线逐项A/B，避免同时改三项无法归因。累计加速目标为代表工作负载至少1.2倍；这是优先级目标而非硬性否决，小而稳定、实现成本低的改进可单独交付。新缓存须报告首次构建成本及重复多少次才回本。

## 六、P3/P4：GPU验证与采用方式

### 数据流

CPU负责来源/PIT/资格校验与数组准备 → 公共close/掩码驻留GPU → 因子数组上传 → GPU完整截面批量IC/衰减 → 小结果回CPU → 原CPU bootstrap、审核与落盘。

第一轮保持bootstrap原随机消费与汇总语义，不以更换随机数生成器或减少重采样提速。后续只有公式计算占比足够高，才扩为必要字段驻留、完整支持子树在GPU求值。PyTorch关闭梯度，float64为基准，不启AMP/TF32，也不使用FP32宣传性能替代本机双精度测量。

### 配置预算

- 一个GPU worker；按实测空闲显存设置临时预算 `min(4GiB, 空闲显存×60%)`，记录排序索引/临时数组/显存池峰值。GPU与主机内存预算分别执行。
- 日期块只比较128、256、512及不分块四个预定配置。不分块需预估临时工作区能容纳，否则记录资源原因跳过，不实际撞OOM凑记录。旧原型的上传方式有差异，表内必须单列，不将配置差异归因为块大小本身。
- 在已选20个代表中预先固定最多5个作配置选择，剩余作为确认集；每配置3次暖态，机械按正确性、内存约束、真实wall选一项，再在全部代表集确认。禁止不断追加块大小测到某个加速数字为止。
- CS_RANK/Spearman始终保留同日完整有效股票截面；日期分块带足嵌套滚动所需halo。禁止直接展开整个“股票×日期×滚动窗口”的大张量。
- OOM沿既有有限减半机制，直至最小块；仍失败则记录失败并整个候选回CPU，计入最终wall。不得遗漏日期、丢候选或静默声称GPU成功。

### 采纳标准

1. 正确性门槛全部通过，候选/日期/有效数无缩水；支持与不支持公式类别明确。
2. 对照P2后的优化CPU，真实全池代表集目标为GPU热点至少2倍，包含必要回核的完整计算工作流至少1.5倍；冷启动全流程另列，不要求冷启动也必须1.5倍。
3. 加速比使用同配置、同计时范围的中位数，列出各次值和范围。收益落在运行波动内视为未证实。多次复用有暖态收益但首次很慢时，报告启用所需批量/回本点，限制用途。
4. 未达采用标准：交付GPU原型、限制和具体瓶颈，正式入口维持CPU。若热点明确、缩小为一种支持类别可获得收益，可仅该类别通过；不能把不支持候选排除后宣称全清单加速。
5. P4扩支持只限一个预登记完整公式子树类别，优先选P1中占比高、GPU可连续执行者。没有这样的类别就跳过P4。若试后仍无净收益，停止本轮GPU扩展，不扩大到分钟撮合或购买硬件。

## 七、正确性、恢复与最终交付

复用第6包比较器、身份负例与检查点测试，补实际改动的最小测试，不复制整套测试框架。

| 事项 | 最小核验 |
|---|---|
| 数值语义 | None/NaN/±inf、并列秩、常数与近常数、大偏置、负零、边界日期；掩码/计数/排名精确一致，有限误差沿已有算子契约，不统一放宽 |
| 公式与研究决定 | 单算子与嵌套代表对照；月末分数次序、并列组、月IC、方向、门槛决定对齐；不能只比较最终平均IC |
| 跨块与缓存 | 128/129等边界、嵌套halo、源字节变化但mtime不变、股票轴/日期轴/掩码变化、半成品缓存拒绝 |
| PIT与标签 | 训练之后价格哨兵变化不影响训练输出；末端不成熟标签不计入，2025数据不进入读取结果 |
| 失败与回退 | GPU不可用/不支持/OOM可见记录；显式CPU新输出根；新进程中断恢复不重算已验收片或混身份 |
| 公共代码回归 | 包含主仓证券代码变更资格修复；若动到账户公共路径再跑受影响金融负例，不因只做统计要求全部十年重跑 |

CPU保持语义裁决基准。无法可靠检测排序歧义的GPU公式类别不获正式使用资格；研发对照阶段对全部20个代表做CPU核对。正式路径若需CPU回核，明确触发规则并把耗时计入性能，不能隐去。

实施时在 `artifacts/factor-engine-performance-20260913-N/` 取未使用编号，只新增，不修改第6包。交付最小集合：

- manifest：源码与输入摘要、公式ID/正式分母引用、环境/命令/实际backend、测量配置及范围。
- benchmark：原CPU、新CPU、GPU三方分段时间、冷暖wall、RSS/显存、回核及失败记录；实测与推算分列。
- equivalence/recovery：正常路径、已知缺陷与关键负例、新进程恢复/回退结果。
- source/diff及review：最小差量、支持集、采用裁决、剩余限制、可复跑命令。

运行命令由P0在确认现有入口后实际验证并冻结，交付时必须可复制运行；本计划不虚构尚未实现的CLI参数。旧worker的pure回退仍需显式 `--backend pure` 和新输出根。

本轮完成的定义是：有效CPU改进有证据交付、真实全池有限样本的GPU路线得到可复现裁决、接线/回退和限制齐全。GPU暂缓也可完成性能验证阶段；T1/T2整改未闭合或正式切换未验收时，这些独立阶段继续保持未完成。
