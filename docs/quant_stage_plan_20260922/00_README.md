## 最省事的启动方法

把完整计划包交给实施agent，再发送 `prompts/01_start_C0.md` 的正文。它只能完成C0并停止。将产物交给独立审阅agent，用第二条指令验收。不要一句“全部按计划做到结束”放开全部权限。

C0通过后可一次授权工程批次C1—C4，但每道技术门仍要独立检查。C5是有边界的归因复算；只有留下线索才另批C6。C6最多32配置、C7最多20配置；没有合理方向就提前停止，不必用满预算。C8新的验证和2025+仍锁住。

## 检查工具实际用法

Python 3.10+，无第三方依赖。路径从自己的解压目录和真实证据目录填写。以下不是回测命令，也不下载任何内容。

```powershell
python .\tools\check_delivery.py --report .\templates\stage_report.template.json --root .
```

对空模板应返回退出码2和 `EVIDENCE_CHECK_FAILED`，因为它未执行、缺证据。真实交付时把参数改成agent提交的阶段报告和证据根目录。根目录可以含中文；报告里的证据路径必须相对这个根目录，禁止用绝对盘符或`..`越界。

```powershell
# 只运行本交付工具的合成自测，不读取量化项目数据
python -m unittest discover -s .\tools -p test_check_delivery.py -v
```

返回 `EVIDENCE_FILES_OK` 只说明工具覆盖的文件/身份检查一致，不说明日志未被伪造、不认证审阅身份、不说明阶段经济语义正确、不授权下一阶段。真正的审批由用户/独立受保护环境持有。实施agent若拥有所有文件和管理员权限，不能靠提示词或JSON阻止它自改证据。

## 基本审阅纪律

工程通过、策略有增量、账户达标、后续验证通过是四种不同结论。严禁“运行结束＝验收通过＝策略可实盘”的跳跃。报告必须同时写事实、推断、未知、未执行与下一步权限。失败结果可以是合格交付，伪造完成不可以。
