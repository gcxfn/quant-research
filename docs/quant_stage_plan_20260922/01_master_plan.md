## 1. 项目要实现什么，以及本计划不承诺什么

### 1.1 最终业务目标

在统一的 **500,000 元**账户内，以 **个股为主要收益来源、现金为防守资金**，研究税费后复利年化 **严格大于 10%**、每日账户权益最大回撤幅度 **严格小于 20%** 的历史可行策略。账户级结果包括全部闲置现金；不以股票投入部分的年化替代总账户成绩。

不要求每个自然年都赚 10%，也不将历史回撤当作未来损失上限。研究阶段可设置早期机制门与稳健性门，但不能把通过早期门写成最终目标达成。不存在“历史一条曲线达标，即保证未来达标”的验收。

### 1.2 当前已知状态：事实与解释分开

下表是本计划使用的起点；来源见末尾 S01—S09。实施时必须再次锁定当前提交，检查是否已有后续工作，避免覆盖更新。

| 已有材料支持的事实 | 本计划如何使用 | 不得扩展成的结论 |
|---|---|---|
| 阶段 A 有当前基线 v4；FULL-bin 全窗口净 CAGR 约 −2.90%、MDD 约 −27.29% | 作为旧口径复现和受影响范围分析的锚；不是盈利候选 | 全部历史路线都已按 v4 复验 |
| 阶段 B 四个主候选 A1/A2/B1/B2 全部负收益 | 原失败记录保留；不递补进验证期 | 所有个股趋势、事件或 ML 永久无效 |
| B1 102 个事件，63 个 `skip_slots`，39 个签发、35 个成交、4 个 `cancel_cap` | 优先分离席位选择与订单选择 | 67 个未参与事件全因限价未成交 |
| 归因脚本把未匹配事件统称 `unmatched`，成交后收益以成交日收盘复权序列起算 | 需针对性修订归因口径 | 真实买入成本起算的净优势已被验证 |

| 部分旧 fixed-scheme/K10/风控比较仍待复验 | 依赖这些结论时再验证 | 为形式完整立即把全部历史试验重跑 |

**状态原则：** 旧产物的“当时运行结果”与“当前可用于科学推断的有效性”分别记录。发现新缺陷可以把受影响的结论标成待复核，不能删除旧阴性结果，也不能继续无条件引用有缺陷的旧阳性结果。

### 1.3 两个彼此独立的成功标准

**工程成功：** 能够对同一输入、合同和版本，独立重建交易、资金与权益；差异可解释，违规时阻断，证据可追溯。

**研究成功：** 在工程可信的前提下，识别出有合法可兑现优势、满足账户目标且经后续检验的机制。正确得出“本轮没有找到”仍是研究交付完成，不是可实盘成功。

### 2.2 可优化，但只能在正确阶段按预登记修改

每席初始预算、现金比例、D3 或其他账户风险规则、恢复条件、分批止盈策略、持有窗、信号排序、席位接纳优先级、在合同允许范围内的具体限价生成、事件冷却、候选池中的非硬性质量过滤，都属于研究选择。

它们不是市场强制规则，也不是因为已经写入代码就永久正确。**同时，它们不允许在工程对账阶段顺手改动。**每个实验改变的维度、理由和对照必须明确。每席 10% 是当前控制组参数，不是本轮不可变资金规则；不能把“最多25%”偷换成“每次必须25%”。

### 2.3 规则冲突的处理顺序

1. 已能定位的用户明确指示决定目标、授权和不变边界。
2. 已批准的交易合同决定现实模拟语义；新计划不得悄悄放松。
3. 新阶段签署的协议决定该阶段的方法、门槛和预算；旧阶段按旧协议留档。
4. 代码是当前实现事实，不是自动正确的规范。
5. README、报告的解释和 agent 的推断不是规则来源。

C0 必须生成 `contract_conflicts.csv`。每一行写冲突双方、证据位置、影响、拟处理和是否需用户裁决。对已有明确指示的“个股主收益/旧ETF主线冲突”可起草修订；对未明确的成交、费用、样本权限不得擅自裁定。不得反复询问用户已经明确的50万元或个股方向。

## 3. 对实施 agent 的控制方式

### 3.1 至少拆成三个职责，不允许自签验收

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 用户/负责人 O | 批准范围、预算、样本打开和关键规则改变；最终决定是否继续 | 不承担逐行代码复核义务 |
| 实施者 I | 在授权文件范围内实现、测试、登记原始证据 | 修改硬规则；自己给阶段签“已验收”；代签用户/审阅者；自行消费 Val |
| 独立审阅者 R | 从合同和输入出发算预期值；独立重跑；挑战报告因果和口径；给技术意见 | 只读实施摘要就批准；直接改实施分支同时给自己批准 |
| 运行/归档责任人 K | 隔离数据、执行获准命令、保存不可变日志/摘要、发布复核证据 | 修改策略或验收预期使结果好看 |

个人项目可以由用户承担 O/K，由两个独立会话承担 I/R。不同会话仍可能有共同模型偏差，不得称为绝对独立第三方；独立性还必须来自不同实现、事先写定的预期、受保护的证据和实际复算。只有一个 agent 时分两轮做也有帮助，但不满足核心 C2/C3 的独立实现验收，不能伪造第二签。

### 3.2 技术权限优先于口头要求

建议新阶段采用独立分支或 worktree；实施者不直接写 `main`，不能 force-push，不得改历史运行或原始数据。核心目录、验收脚本与协议变更需要复核。GitHub 支持所需 PR 审批、状态检查和新提交后旧审批失效等能力；是否已启用要由权限审计确认，不能只提交一个 YAML 就称安全机制已生效。[M01]

若 agent 与用户共用管理员凭据、能改规则和所有证据，“禁止自签”主要仍是流程约束。应由用户保管合并/验证数据权限，或者由独立环境执行核心检查；不能声称文件中的 `reviewer_id` 字符串证明了真实审阅。

### 3.3 三种状态不得混用

- **运行状态：** `not_started / running / completed / failed / aborted`。
- **工程验收：** `pending / accepted / rejected / blocked`。
- **研究判定：** `not_evaluated / no_edge / insufficient_evidence / promising_not_validated / target_met_in_dev / validation_failed / validated_historical`。

`completed` 只表示进程结束并留下结果。工程 `accepted` 不代表存在优势。`target_met_in_dev` 不代表已获验证授权或可实盘。历史回测 `validated_historical` 仍不构成未来回报保证。

### 3.4 一票阻断项

任何未来信息参与决策或未经授权的验证收益计算；硬规则漂移；缺失真实日志却声称执行；改测试预期迁就代码；吞异常返回“安全默认”；删样本美化结果；重写归档；签名/审核来源无法核实；预算超额；来源文件身份不一致；现金、数量或订单生效时间无法对上。

发现后停止**受影响的推进链**，保存现场，标注受影响 run，提出最小修复。无关、独立且已批准的工作不必全部停机。

### 3.5 缺陷级别和返工上限

`CRITICAL`：越权、未来信息、会计/成交违规、证据不可追溯。`MAJOR`：会改变主判断的统计或策略接口错误。`MINOR`：不改变交易和主要数字的文档/展示问题。

核心门验收时 CRITICAL 和阻断 MAJOR 必须为零。MINOR 可延期，但要有责任人与退出标准。同一根因最多两轮修复后若仍无闭环，应暂停该实现路径，提交缩小范围/替换责任人/重设计接口的决策；不是允许只修两次后带错过关，也不是立刻重写全项目。

## 5. 阶段 C0：接管、去冲突与证据冻结

### 目标

把“用户要什么”“合同允许什么”“仓库目前是什么”“哪些结论已失效”写成可核对的四张表。只做现状接管，不扩大策略、不修改引擎。

### 进入条件

用户明确授权 C0；可读取当前工作树、提交历史和 A/B 关键产物。只知道本机 `D:/量化` 路径而无对应内容时不能伪造读取；仓库路径能解析则优先读取，不要求用户重复上传。

### 方法与步骤

1. 记录 remote、branch、HEAD、工作树状态；列新增未提交文件。不要执行 reset/clean/stash 来“清洁现场”。新运行应来自隔离干净代码快照；未知未提交内容不能暗中成为依赖。
2. 以当前 HEAD 与本计划基准差异清单判断是否已有 C 类进展。找不到不等于不存在；明确搜索范围。
3. 读取 `AGENTS.md`、主计划、交易合同、A/B预登记、有效 run manifest 与 `affected_runs.csv`。记录根指令是否仍误导到 ETF 主线或允许覆盖50万元。
4. 建立 `contract_snapshot.json`，记录每条值、来源、有效范围、变更权限。旧文档与实现冲突先列出，不用代码事实反向改规则。
5. 建立 `evidence_index.csv`：文件、blob/内容摘要、run、版本、可用性、原判定、当前证据状态。原 A/B 不重写。

## 6. 阶段 C1：数据隔离与接口合同

### 目标

让“不看未来”不再只是报告的一句话；把价格、事件、订单、成交、持仓、统计之间的接口先冻结。核心是数据的可得时间，而非仅以日期过滤。

### 方法

**物理与逻辑隔离。** 由 K 用受控过滤导出 Dev-only 工作集；研发运行只挂载该工作集，不挂载全年的原始文件。需要2015年前预热可沿已批准历史数据使用，但只能作为特征历史，不加绩效年份。若基础设施只能读混合文件，由受控提取任务记录只输出许可范围、禁止显示禁区行情或统计；执行 agent 不直接拥有绕过过滤的全数据路径。

每个数据表最少有事件发生时间 `event_at`、公开可得时间 `available_at`、样本可评价终点 `label_end_at`、来源和版本。只有披露日期没有时分时，沿既有保守 B1 时钟：公告当日收盘后视为可得，下一交易日11:30最早决策；不擅自提前到开盘。

**逐类数据卡。** 日线/半日 bar 的单位、官方收盘与 pm.close 桥接、历史停牌/ST/上市权限、涨跌停表、送转与分红现金、预告历次版本和相同财务期键、缺失与终止证券的处理分别登记。数据字段 `update_flag` 不是天然证明旧版本当时可得；需原始版本或来源说明，不能以最新公告回写旧值。无法恢复版本则该事件不具备可靠PIT证据，显式列出。

**边界处理。** 所有20日标签必须同时保存实际终点。边界不完整事件保留、标记 `window_complete=false`，不混入完整窗口均值；对照同一终点，不用“各自20个自身交易日”导致比较跨不同市场日期。策略持有年龄仍按旧合同自身交易日，评价同时提供固定市场日口径以解释停牌资本占用，二者不得混同。

**预测/训练/评价分开。** 当期候选全集只由当期资格决定；未来缺失标签不能删掉当期候选。训练集只取已完整可得标签；任何终止或缺失结果都要披露，无恢复行情不可拿后来年份报价强行结算。不得把现金分红/送转既计到账本又重复叠加复权收益。

**冻结接口。** 参照 `04_evidence_spec.md` 形成小型、版本化数据对象。参考账本只吃规范化成交和公司行动，独立matcher只吃具体订单与行情；主引擎给实际具体订单时不得只提供最终成交。

### 必测反证

修改决策后价格/未来资格，当前候选与订单必须不变；修改午后行情，11:30输出不变；缺失/过期数据拒绝新入场但保留风险处理；2020-12-28事件20日窗被标不完整；真实Val文件路径不在许可挂载范围时读取失败；重复公告、同日修订、精确点预测 `min=max`、非法区间 `min>max` 各有独立测试；时间字段空值不自动落到当天。

### 交付物与验收 / G1

Dev数据manifest、数据卡、接口版本、时间边界测试和真实执行日志、缓存键规格、权限演示。验收要求：所有研究接口无未经授权输出；关键时间断言100%覆盖；数据缺陷范围明确；没有通过删除困难证券或未来标签缺失样本掩盖问题。若正式统计所需数据不可得，阶段可 `blocked`，不得继续跑好看的曲线。

## 7. 阶段 C2：独立参考账本——先证明钱和股票算对

### 目标和边界

给定完全相同的成交记录、分红送转和估值价格，独立算出现金、可用现金、待结算资金、持股、可卖股数和权益。不选股、不判断该笔成交是否应发生，不调风控、不重建第二个大型回测平台。

本阶段回答“账是否对”，不能单独回答“成交是否真实”。参考实现只共享数据格式与已冻结合同，不调用主引擎的费用、公司行动、现金结算、FIFO、估值或收益函数；使用标准库 Decimal/整数分与简洁循环。独立审阅者先写手算预期，再读主引擎输出，防止按现有结果倒写答案。

### 实施方法

1. 定义事件排序：半日开始前公司行动/结算、许可成交、半日估值、决策；以合同为准并逐项标注。金额舍入位置与方式必须冻结，不能因误差而在两个实现各取一种。
2. 输入至少含 opening balance、具体成交、实际费用字段、公司行动、官方估值、半日结算节点。订单预算冻结资金、已支出现金、待结算卖出款须分开，不得同时重复加进权益。
3. 参考实现独立计算费用，并与成交中记录的费用比较；不要只信任主引擎给的费用总额。
4. 股票数量逐证券逐批次滚动；可卖量按取得日检查；持仓成本与现金流分开。部分卖出是否消耗FIFO与策略批次风险如何对应，先沿合同核对，语义冲突交C3/C4，不自行改。
5. 每个事件点验证：`权益 = 现金总额 + 持仓按规范估值的市值`；现金总额中可用与待结算款不重复；持股增减与成交/公司行动对应。已实现与未实现损益只用一种成本体系，报告其加总与权益变化的桥接。
6. 先跑 `05_test_vectors.md` 的手算数据，再回算 v4 FULL-bin、NOSNR、NOACCT，以及阶段 B 四主臂和三条随机对照已有成交账本。这里只重算账本，不重做信号和回测；大体量可分证券/日期检查但最终必须覆盖所选运行全部事件。
7. 主引擎没有输出必要中间状态时，可先读取已有输出；确需增加日志时，只做同配置插桩回放，记录为工程重放，并证明核心经济结果未改变。不能用缺字段为由编造中间状态。

### 数值验收

合成案例现金/费用/股数按事先约定精确到分或整数完全一致；同合同舍入后的真实账本每个节点应一致到分。浮点实现与Decimal如有最终一分差，逐个列明原因、发生节点、累积影响，由审阅者判断是否纯数值表示；不得用“累计笔数×一分”大容差抹平经济错误。未解释的金额差、T+1差或股数差为阻断问题。

成本提高的单调性测试只针对**固定成交序列**：费用提高后净权益不能更高。动态闭环策略可能因费用改变仓位/交易路径而不单调，禁止把固定路径不变量错误套到所有策略上。

### 交付物

参考账本源码及单测、手算预期表、`ledger_reconciliation.csv`、逐类费用对账、`reference_independence.md`（导入与共享依赖扫描）、所有选定run的完整差异清单、独立重跑命令/日志。

### 验收 / G2

固定输入来源一致，核心运算代码独立；合成和真实范围内没有未解释的金额、股数和结算时序差异；至少一个审阅者独立重算费用、分红和多批次卖出。只输出“该范围内账本一致”，不得直接升级为“引擎完全可靠/可实盘”。

## 8. 阶段 C3：独立成交核验与公共策略衔接

### 目标

分开确认：①明确的订单是否被合同正确匹配；②策略表达的价格、数量、有效期是否真正传到订单层；③席位、退出和风控是否发生非预期交互。

### C3-A：同一份具体订单，第二种实现判断成交

先把主系统输出落到 `order_id` 级：证券、方向、数量、限价、创建时刻、生效半日、到期、意图、来源、替代关系。只给 `target_weight` 而没有解算后的限价/数量，不满足本阶段输入。

独立matcher只用这份订单、许可半日OHLC、历史限制和同一资金合同。它不调用 `band_engine` 的穿透、价格合法性、订单生命周期函数，不调用策略选股。两个层次分别验收：固定订单的开环匹配；随后用小型确定性策略的闭环状态响应。固定订单一致不能替代闭环一致。

必测：`low == buy_limit` 不成交、严格小于才可能成交；卖单对称；跳空沿旧合同按限价不取优；停牌/非法价/涨跌停边界；当半日新买不可卖；同半日卖出款不可用于当半日新买；过期、撤销、替换、迟发订单；风险单三半日未成交后的下一个许可半日兜底；停牌冻结计数；止盈不获风险兜底；同一订单重发不能成为多笔独立交易。

对固定订单核对：是否成交、日期、半日、股数、价格、费用、未成交原因、末状态。核心字段要求一致；不得只看最终CAGR近似。

### C3-B：策略到订单的语义链

**入场上限。** 明确“触发价×1.01”到底是签发条件、具体限价，还是重发门槛。归档provider并未把该上限作为独立限价字段直接交付；必须追踪到引擎最终价格构造，不能只测provider布尔判断便声称实际订单价正确。[S05/S06]

**席位账。** `held + active_pending` 计数需可重建；完全失效挂单释放席位、部分成交按合同计席、同证券重复事件不占两席、离场未完成仍按持仓约束处理。一天大量事件时，明确谁被接纳、谁未签发，以及当时的已有持仓与优先级。

**风险预算。** 每席10%、D3缩放是策略配置，必须实际打印正常/降档目标、真实暴露、恢复队列。增加合成路径：亏损触发降档后、正常反弹和持续低迷时分别怎样恢复；不能根据恢复后恰好赚钱才选择阈值。

**退出与批次。** 风险止损、保护线、部分止盈、全部止盈、时间退出、席位退出、账户减仓分别映射订单。触发/签发/部分成交/完成不同；`take_half` 不得因触发即标完成；持续重发冻结同一事件ID；外部清零清理状态；FIFO消耗与逐批风险意图错配必须明确。未解决错配时不能用于含相关多批策略的下一阶段。

**优先级。** 同一证券同时止损、时间退出、账户回补等冲突，按合同唯一优先级处理，并证明不会卖完又同点买回、超卖或将止盈升级为风险单。

### C3-C：合同正确与现实近似的界限

严格穿透、跳空不取更优价、半日无法观察先后，是现有模型选择。模型一致并不证明交易所逐笔成交会完全相同。只用已授权Dev分钟样本核验“订单生效前穿透”不得误计、停牌/跳空情形和半日范围；不打开新高频数据搜索。没有订单簿时不能证明排队成交率。任何模型校准只做差异披露，不改变本輪正式合同与费率。

### 交付物与验收 / G3

`order_reconciliation.csv`、`intent_to_order_trace.csv`、`seat_lifecycle.csv`、`risk_state_trace.csv`、`clip_exit_trace.csv`、合成/真实案例报告、合同局限列表。验收要求：独立matcher在固定合同与指定范围一致；公共策略衔接可追溯；所有核心场景和反证测试通过；没有因利润更好而放松假设。

现实可得性证据不足可限定使用范围。例如当前只能证明主板半日合同，不得声称覆盖创业板或所有分钟路径。范围限制不等于可无限延期修基础设施。

## 9. 阶段 C4：定向修复、最小重放与公共系统裁决

### 目标

对C1—C3证明的缺陷做最小修复，明确哪些结果被改变。给出可以开始研究、需要继续阻断或应当重设计局部接口的决定。

### 方法

每个修复必须包含：缺陷ID → 合同条款 → 最小失败样例 → 独立预期 → 补丁 → 针对测试 → 受影响运行 → 差异解释。禁止“重构一遍顺便修好”的大补丁混入多个未登记策略改变。

账本问题优先修会计；matcher问题修订单实现；策略不合适则作为新研究规则，不冒充工程bug；统计错误只重算受影响统计。判断规则本身是否合理，与代码是否正确执行规则分别立项。

真实重放范围按依赖图决定：涉及共享账本/撮合则覆盖v4基线、四候选及三随机对照的必要锚；仅归因公式错不需重做全部交易；旧K10等如果不依赖其结论，不排本轮。退出被改动时仍要保留NOSNR等不经过退出模块的阴性控制，确认无关路径不变。

修改后的“期望结果”必须来自合同/独立算法；不能通过改测试断言接纳代码。允许纠正被证明错误的旧测试，但必须记录旧断言为何错、证据与审阅结论。新执行版本从独立代码快照启动；源码/配置/关键输入起止哈希一致，运行中被改写即中止。

### 必须关闭或收窄的旧解释

1. “未参与”不能统称“限价未成交”；“成交后”必须说明是否从真实成交价、是否含成本。
2. 首年收益以初始资金到首年末计算，不能漏首年再宣称全期每年负收益。
3. 不把IDEAL/FULL等同时改变多个维度的CAGR差称作纯执行损耗上界；不把不同路径的CAGR差加减成唯一信号残差。
4. BM2微额持仓最低佣金伪影不得充当有效可投资基准；旧判定留档，新协议另设基准。
5. `22次`等组预算与实际独立配置、种子、压力、查看过的结果维度分开记账。不要认定多臂同进程只算一次；也不要把相同配置工程复现夸大成独立发现。
6. 已发生Val标签接触不可用后续清洗抹去；对受影响窗口精准登记，不夸大为全部样本永久不可用。

### 三种裁决

**ACCEPTED_SCOPED：** 合同内、所用范围内完成独立对账和撮合检查；剩余局限不妨碍下一阶段。

**BLOCKED_FIX：** 存在会影响核心判断的缺陷；只修指定模块，不开新策略。

**BLOCKED_REDESIGN：** 接口无法表达批准的交易语义，或同根因两轮仍无法闭环；提交局部重设计/负责人替换提案，不自动推倒全部仓库。

### 验收 / G4 与工程退出条件

证据缺口和CRITICAL为零；阻断MAJOR为零；受影响锚已复算；未影响锚语义一致；差异逐项可解释；所有旧版本只读保留；主计划、run索引、问题表、受影响清单同步。总体报告写清“通过了什么范围、没证明什么”。

**达到G4即停止无收益关联的工程扩张。** 更换框架、增加数据库、全市场分钟回放、界面重写均不属于本阶段。只有新暴露的阻断缺陷才能重开工程门。

## 10. 阶段 C5：修订失败归因与 B1 的第一道证据门

### 目标

不重写旧失败判定，利用已有事件和运行证据回答：B1是否有足够的开发期线索值得做小规模执行结构实验？将“可观察漂移”和“可交易净增量”明确分开。

### 10.1 全事件接纳漏斗

事件记录必须有唯一 `event_id`；订单与成交用ID关联，不用“同股票三天内第一笔买入”代替唯一身份。原事件数102等只作为复现锚；若PIT/字段/边界修正改变样本数，保留旧集、新集及每条加入/退出理由，不能强行凑原数。

生命周期分两个表：事件决策表在触发时给出互斥初始去向（已有持仓/已有挂单/满席/新入场阻断/缺锚/追价资格失效/已签发等）；订单表跟踪签发后的未成交、取消、部分/完整成交。每一步数量守恒，不能把多次状态转换重复相加为多个事件。

比较至少包含：全部事件、被接纳事件、满席未签发事件、已签发未成交事件、已成交事件。对B1尤其单列63与4两组，才能检查限价与席位解释。漏斗是描述证据，不凭一张条件均值表宣布因果关系。

### 10.2 重新计算收益

- 事件诊断收益：统一合法信息锚，20日完整窗口；同步匹配同日期对照。
- 实际成交起算的20日诊断收益：真实成交成本，期间分红/送转正确衔接；真实可退出窗口不足则不得假定按收盘必卖。可分“20日标记收益”与“按冻结订单退出后的可执行净收益”。
- 账户实际交易收益：按真实仓位、部分退出、费用、风控和现金占用重建；不得把诊断20日收益替代实际策略损益。
- 费用按成交与退出的实际名义金额，价格跨公司行动时统一股数口径。报告毛/净时使用同一路径，不用不同策略曲线代替费用消融。

至少输出均值、中位数、10/25/75/90分位、胜率、盈亏比、尾部亏损、独立证券数、公告日期数、每月/每年样本数与损益。对个股1/5笔最佳交易移除、整月/整公告簇剔除做敏感性，保留全样本为主，不把裁剪后的最好结果当新主结果。

### 10.3 合理对照与样本聚集

全池均值与全池中位数分别回答不同问题，均需准确命名。主增量采用同日、同合法起止窗口、同费用和可成交约束的匹配对照；不拿股票均值减池中位数就称可投资超额。

匹配信息只能用当期行业、市值、流动性、价格/波动等；匹配规则和变量一次冻结。行业或历史市值缺失不得用当前分类补历史；优先报告缺项和限制，不能无限获取新数据。对照证券资格必须当期有效且不含被研究事件本身。

事件重叠、同公司多次公告与同日行业行情不能当大量独立样本。用公告月份分块和证券聚类两套固定方法报告区间；均保留完整日期簇。有效日期簇很少时区间仅作诊断，明确“证据不足”。不把随机种子数当独立市场年份。

### 10.4 B1 的“类型改善”与“数值上修”必须拆开

冻结两种证据标签：`type_improved` 与 `numeric_revision_up`，列二者交集与独有。数值上修需同一财务期、可比净利润单位、历史版本、合法区间；`min=max`可表示点值，是否允许由数据合同确认；缺失数值不能被类型分支伪装为已检验数值上修。

当前类型排序只是既有研究定义，不将“续亏→首亏”等标签顺序天然解释为同一期盈利经济改善。抽核全部B1事件的源字段；102量级无需只抽三条就宣布全部正确。若无法证明历史版本可得性，标记该组不具可靠PIT基础。

本阶段可以完成事实纠错与诊断，不据结果反复选择新的类型顺序、阈值或持有期。新增数值-only交易臂属于C6的独立申请，不自动加入四臂实验。

### 10.5 第一门的判定（不是10%/20%门）

先验硬门：时间合规、成本/成交口径可复核、样本不会因未来结果被筛、数量守恒。硬门不过，只有 `invalid_evidence`，不讨论策略盈利。

证据分三级：

- `no_edge`：在主要匹配口径下净增量不为正，且无法解释为单一已证实实现问题；停止该实现。
- `insufficient_evidence`：点估计为正，但聚类区间跨零、独立日期/证券不足，或结果由极少簇主导；不送Val，不宣布验证。允许提交“补历史PIT覆盖”的独立提案，而非继续调规则。
- `promising_not_validated`：主口径合法交易或明确可交易影子票据的净增量为正；预登记的90%聚类诊断区间下界为正；主要分段方向与机制相符，未由一笔/一簇独占；所有限制披露。只允许进入C6小规模Dev机制实验。

90%只是本计划建议的研究资源分配门，须在重算前冻结，不是显著性或未来成功概率保证；既有Dev被反复查看，不能将该门称为全新假设检验。若重算前未冻结，则该轮只作探索，后续不得追认。

### 交付物与验收 / G5

新归因CSV、旧新事件diff、旧新指标diff、源字段核对、匹配对照、集中度报告、样本边界清单、三分支建议。没有C5“可交易”证据时，C6只能作为经明确批准的诊断实验，不得声称已有净优势只欠资金配置。

## 11. 阶段 C6：有限的席位 × 订单结构实验

### 目标

只对C5留下的一套冻结B1事件定义，检验“接纳谁”与“如何下单”的区别。不是新开四个策略家族，也不是承诺通过修复把B1变成达标策略。

### 进入条件

G4已通过；C5证据报告完成；用户授权本阶段Dev预算；预登记列出具体事件集、S/E两种规则、输出指标和判定。账户、费用、时钟、最多4股、单名25%、当前持有退出和D3保持不变。本阶段不同时改资金比例、止损、持有期或新增数值-only信号。

### 11.1 四个主臂

| 臂 | 席位接纳 S | 订单生成 E | 核心问题 |
|---|---|---|---|
| S0E0 | 经C4修复后当前规则 | 经C4修复后当前规则 | 可复现控制组 |
| S1E0 | 去掉同一时点股票代码优先的中性接纳 | 当前规则 | 股票代码排序是否造成特殊样本选择 |
| S0E1 | 当前规则 | 显式追价上限限价单 | 具体挂价是否影响捕获与净收益 |
| S1E1 | 与S1E0完全相同 | 与S0E1完全相同 | 两个改变有无交互 |

**S1默认精确定义：** 不替换正在持有的股票，不扩大席位，不延长事件有效期；在同一决策时点、资格/风控允许的新事件中，以 `SHA256(salt | decision_at | event_id)` 升序接纳剩余可用席位，主salt固定为字符串 `20260922`。该规则不使用未来收益，不声称优于财务排序；用途是测量当前股票代码排序的偶然影响。中性接纳也可能失败，不能事后换salt挑赢家。

如用户希望测试“按经济修订强度排序”，须另立S1定义并在运行前替换默认、保持四主臂不增加；不能两种都跑后择优。优先完成中性排序诊断，再决定是否值得开发新排序因子。

**E1默认精确定义：** 在原B1合法决策点，以当时可得锚价生成固定上限 `cap=floor_to_tick(anchor_at_first_issue×1.01)`；为下一许可半日实际提交的买入限价就是该cap，而不是只用cap过滤后仍隐式按别的锚价挂单。后续许可半日仅在原TTL与失效条件内按同cap重发；超过cap资格、信号失效或三次原定机会耗尽则停止。成交仍严格穿透、按该限价、不取更优价；历史价格合法性和全部费用合同不变。

不得借E1跳到公告次日开盘买入、同半日改单或放宽涨停成交。下一半日价格上下限必须由合法时点能知道的信息处理；未知价格边界由现有matcher合法性规则拒单，不能偷看未来OHLC来定价。

C3若证明当前E0已经等价于上述E1，则该臂没有处理差异，不能报告“优化无效”的研究发现。应在运行前取消该因素或提交一个有机制理由、不同且合规的E1；不为了凑四臂杜撰参数。引擎缺显式限价接口时，先做最小附加字段与零回归，过工程复核后再跑，不把接口补丁与策略收益混为一谈。

### 11.2 总预算与实验计数

建议本轮上限 **32个已注册输出配置**，逐臂计账，不按进程或组名压缩：4主臂；8个额外固定salt ×2订单规则共16接纳随机对照；4主臂×延迟半日/一交易日共8压力臂；4主臂×额外不利摩擦情景共4压力臂。

额外salt固定：`11,23,47,101,211,307,401,503`。它们是排序敏感性对照，不作为8个独立市场样本，不从中挑最高收益用于生产。技术重复运行和同一配置复现单独计 `engineering_replay`，所有查看过的收益也登记 `result_view`。

额外摩擦是**压力账本情景**：在冻结基础费率之外，按成交名义每边0.2%额外现金损耗测试资金路径；明确这不是新的真实费率，也不把成交价改到违反买入限价的位置。必须闭环重算资金/订单影响，不能只从最终净值减一个数字却声称已做完整执行压力。若未具备这种能力，标“诊断近似”且不可作为稳健性验收通过。

延迟包装必须使用经过C3验证的TTL/订单ID生命周期：延迟后原已失效/取消的单不能复活；不能为改善成交率顺延原失效时间。先在合成场景测试，再进入压力臂。

### 11.3 评价方法

首要指标：真实可执行净增量、全事件到可用席位再到成交的转换、平均投入资金、尾部风险和每日账户权益。辅助指标：数量/名义双口径成交率、等待时长、错过组收益、年度和公告簇分布。

成交率本身不设“必须≥90%才能有优势”的新普遍定律。高成交率可能买入更多坏交易，低成交率也可能有正净收益；旧阶段90%门原样留档，新阶段分别评价执行可靠性和经济收益。

用同一初始资金下四臂的期末净财富/共同日期收益做配对比较。可以报告S、E及交互的**模拟政策差异**；不能用条件样本均值宣布现实市场因果，不能把全体未交易事件假装都可同时持有。单笔影子票据只作机制诊断，不能加总成突破四席/资金约束的组合净值。

### 验收 / G6

32臂以内、全臂留档、配置冻结、硬约束零违规、随机对照不挑种子；至少一个候选在合法净增量上有可解释改善，且压力没有把优势完全抹掉，才有资格提名C7。最终最多2个实现，使用预登记的优先级（有效性→稳健性→较低复杂度→净增量）选择，不只取最高年化。

若只有去代码排序的某一个salt赚钱，判排序不稳定；若全部净增量为负则关闭该实现；若成本前正成本后负则归类不可兑现；若事件太少则证据不足。没有结果也不得返工成另一个未登记“版本2”。

## 12. 阶段 C7：统一账户的风险预算与10%/20%可行域

### 目标

将通过机制门的个股候选放进同一个50万元账户，研究如何分配资金与控制回撤。不是把多个各自50万元袖套收益做加权就假装共用资金。

### 进入条件

G6通过，候选规则冻结；不再修改事件定义、排序和入场来追逐目标。保留可选时钟、所有账户/交易硬约束。若只有少量事件级优势，先计算资本占用与机会密度再申请账户优化预算。

### 12.1 先做收益和资金使用预算

按真实交易机会、互相重叠、持仓天数、名义金额和尾部损失估算账户可能性。输出平均/峰值股票暴露、空仓时长、满席天数、闲置原因、单位资金日净损益、事件拥挤月份、不同起点净值。

`年交易数 × 平均单笔仓位 × 平均净收益`只能作无重叠/近似线性假设下的粗预算，必须披露假设；不能用7%/20日直接乘12，也不能仅凭旧35笔成交认定所有新结构密度不可能达到目标。

### 12.2 先风险方式，再资金规模，不做全笛卡尔网格

本阶段默认最多 **20个完整配置**，以1个C6主候选为主；第二候选只作相同已冻结最终配置的复核，不自动翻倍预算。多个候选需要组合必须先证明信息/亏损差异，再独立登记。

**第一组：4种账户方式，基础每席10%不变。** 当前D3；不加动态账户减仓的控制组（个股硬止损与市场约束仍在）；慢市场趋势风险门；只减不加杠杆的波动预算。后两种规则须在本组运行前冻结，建议沿已有可核验组件而非新增复杂模型。具体指数、预热、阈值、最低/最高规模、恢复确认和冷却不得留运行时默认；缺任何一项不允许运行。这里是在开发期研究风险方式，不授权实盘取消账户控制。

**第二组：最多6种规模。** 从第一组按事先标准最多选2种风险方式，各研究每席15%、20%、25%；其他完全不变。25%订单需扣费用并遵守单名/总资金约束，不能强买四笔整25%导致费用不足；不悄悄改变仓位帽语义。

**第三组：最多2种退出诊断。** 只对已选实现比较一个有机制理由的替代退出（例如取消非硬性固定全部止盈，改已验证移动保护线），保持硬止损与其他维度不变。若C6优势依赖当前退出，该实验是新规则研究，不可将其结果追认到C6。

**第四组：最多8个压力配置。** 最多2个候选×4压力：原合同上额外不利摩擦、额外半日延迟、额外一天延迟、预登记的资金占用/同期事件拥挤情景。不能挑压力比较温和的子样本。

合计4+6+2+8=20。若第一组没有正净优势，后续预算自动停止，不必花满。少于预算不是交付失败；超过预算须新授权。

### 12.3 三道目标门分别列示

**有效性门：** 数据PIT、独立账本/撮合、真实成本、账户约束全部合规。

**经济门：** 在统一评价窗，全账户税费后CAGR>10%，每日MDD幅度<20%；另报告实际可投资期口径、第一年、最长水下期。平均年收益、股票袖套收益、月末回撤不能替代。

**稳健性门：** 邻近规模/规则没有尖锐孤峰；主要成本/延迟压力下不出现未披露风险失控；按年度/公告簇/起点的结论能解释；收益不是仅由一笔/一个簇决定。全部压力结果公开。12%—15%/15%—17%可标“余量充足区域”的工程偏好，不能替代正式门或称保证。

本计划建议最坏预注册压力下依旧满足10%/20%的候选优先进入Val；仅基础达标而压力不达标者标 `fragile_target_met`，默认不晋级，用户可在了解证据后另批验证，不由agent自行放行。

### 12.4 没有可行域时怎么办

分别输出：有个股增量但机会密度不足；收益足够但回撤过大；风控降低风险同时消灭净收益；敏感性太强；或者没有可兑现优势。

不能把失败组件无解释拼起来，也不退回ETF达标当个股成功。可以提交最多2个新收益假设的研究申请，须明确与A/B已有实现的机制差异、所需合法信息、持有周期、证据和成本；未经用户批准不运行。日频检查不等于必须短线持有，可研究较长周期，但不得直接宣称更长周期更赚钱。

### 交付物与验收 / G7

全20以内配置矩阵、统一账本、成交与现金冲突日志、风险状态/恢复路径、分年/起点/压力、收益集中度、参数邻域、所有尝试及阅览账本。结论只能是候选可送Val、脆弱需另批、无可行域、证据不足；不得只发最好一行。

## 13. 阶段 C8：后续验证与最终裁决（单独授权）

### 默认权限

### 方法

1. 固定最多2个候选的代码、数据处理、资本、费率、阈值、排序、退出与权重。所有缓存身份包含配置/代码/时点；禁止以已有全期缓存绕过时间隔离。

## 14. 阶段 C9：手动助手准备与影子运行申请

### 目标

在研究成果足够且获得新授权后，将候选变成能正确读取账户、输出计划、接收真实回填并对账的工具。该阶段的默认交付仍不连接券商、不自动下单。

### 方法与交付

先用合成账户和Dev回放演练：输入仓位/现金/订单版本，输出动作、区间、数量、目标、有效期、失效条件、风险和与上版差异；Day0最多3候选，11:30/15:00只生成下一许可半日计划。

覆盖未成交、部分成交、晚回填、重复回填、撤单、外部手动买卖、费用误填、公司行动、停牌与行情过期；回填前不得假定已成交；回填幂等，外部账户差异必须提示并阻断新入场，不能悄悄改仓位。实盘账户没有agent可用的下单权限。

影子运行需要用户明确授权日期范围、数据源和展示范围，不能以“只是看盘”绕过2025+冻结。在新授权的前瞻观察中，按计划生成时间留痕、不事后更正曾展示的价格，并比较计划与人工可执行情况。工程验收建议至少20个交易日且覆盖关键生命周期；这只是操作覆盖，不是证明策略收益的样本量。

### 验收 / G9

所有关键生命周期可独立重建；新计划与真实回填一致；数据过期/身份不符停止新建议；成本、动作与数量可解释；有故障恢复和用户操作手册。是否投入资金属于另一个单独决定，本计划不预设资金投放方案，更不自动启用实盘。

## 15. 预算、并行与返工管理

### 15.1 每阶段都要先有资源上限

默认单worker，不多agent同时改同一共享文件；测出瓶颈才并行。运行前登记允许进程数、峰值内存、最大输出磁盘、wall-time上限、单次超限处置。按当前电脑实测设置，不能照搬另一机器耗时；没有实测就先用无收益展示的合成/小样本正确性任务做资源探测。

本计划不把预计分钟数作为进度保证。计时是实际日志字段，不能把“计划很快”写成已经完成。超时/中断保留状态和产物，不用相同run_id覆盖重启。

### 15.2 研究预算与工程复现分账

每次有新的信号、池、参数、排序seed、持有/风险规则、成本/延迟情景，都在 `trial_ledger.csv` 登记独立配置；同进程的多个臂分别登记。相同配置工程修复重放登记父run、bug_id与差异，不称新独立发现。

每次查看了什么指标另记 `result_view_log`；冒烟只要看过真实收益也要登记，不能说“零次数所以零选择偏差”。历史不完整的次数标未知，不能编一个精确数字来算显著性。

### 15.3 并行边界

C1接口和手算规格验收后，C2独立账本与C3独立matcher可以由不同agent并行；只读数据审计与文档索引可以并行。共享schema由一个owner维护，接口变更发版本通知并使依赖测试重新验收。

策略生成、风险接口尚未冻结时，执行层不得靠猜字段先写；实施与审阅可分工但审阅者的批准必须针对最终diff。任何新commit、合同、数据或配置改变后，旧批准仅对旧身份有效。

## 16. 每阶段统一验收协议

### 16.1 “完成”的最小证据包

阶段ID与授权范围；代码提交/快照哈希；配置与数据哈希；实际运行命令；起止时间、退出码、资源；完整stdout/stderr；pytest或相应测试的结构化结果；逐项验收ID→证据；所有未完成内容；缺陷级别与去向；独立审阅意见；主计划和台账的追加记录。

测试既给总数，也给本次新增测试ID、运行日志、收集到的数量与skip/xfail原因。出现skip/xfail不能藏在passed数量后面；关键契约测试不得跳过。没运行写 `not_run`，不要输出 `passed:0` 冒充成功。

### 16.2 审阅者最低独立动作

对C2亲算费用/公司行动/现金结算各一例；对C3亲跑一个严格边界、一个K=3和一个撤单/重挂反证；对C5亲算一个真实成交成本起点和一个越界标签；对C6/C7重建配置矩阵并核对全部输出，不能只验证最优臂；对C8核验授权身份和数据挂载。

评语必须写所用证据与具体命令。`LGTM`、“703项测试全绿”、“逻辑看起来没问题”不构成核心验收。独立审阅通过后仍由授权责任人允许推进，不让实施者自己增加stage权限。

### 16.3 证据与权限不是同一件事

SHA256证明文件字节身份，不证明逻辑正确；签字字符串不证明是谁审过；一份通过的JSON不证明原始日志真实。附带 `check_delivery.py` 只能发现格式、缺文件和哈希不匹配，并核对基础run/JUnit证据；它不验会计、不判断Alpha、不认证用户许可。

真实门禁须由可信运行/审阅环境和账号权限落实。若这些尚未部署，阶段报告必须显式写 `enforcement_level=procedural_only`，不能称技术上无法越权。

## 17. 给用户的每阶段一页回报格式

```text
阶段：C? / 本次实际授权范围：……
运行状态：completed / failed / aborted / not_started
工程验收：pending / accepted / rejected / blocked
研究结论：not_evaluated / no_edge / insufficient_evidence / ...

本次真正做了什么：最多三项，与证据对应。
关键验收：通过 X/Y；阻断问题数；延期问题数。
最重要的发现：事实；推断；尚未知，分别写。
结果是否改变：哪些run/哪些数字，哪一层导致。
没有做什么：未执行/未取得/未批准的事项。
独立复核：人/会话、身份、范围、命令、结果与证据。
下一步允许什么：已符合的技术门，但仍需何种授权。
用户需要决定什么：仅列真正不可由已有指令解决的事项。
```

不要求用户先读几十个日志才能知道是否继续。完整证据保留给审阅者；一页回报不能替代证据。

## 18. 立即启动顺序与停机决策

本次先交付计划包，不执行仓库修改。用户将首条指令发给实施agent后，**只启动C0**，提交接管包与冲突表后停止。用户可一次批准C1—C4为工程批次，但每道技术门依然需要独立验收，不能一步跳到新信号。

工程批次通过后，C5修订归因；C5没有足够线索，则本轮可以到此正常结束。需要C6研究预算时再批准；只有C7有合格候选才申请C8，C8默认锁住。

决策树：

- 账本不一致 → 修会计/舍入/公司行动，不换选股。
- 固定订单不一致 → 修撮合/生命周期，不改手续费。
- 账本与matcher一致，但席位/退出/风险衔接不一致 → 修策略接口或另立新研究规则。
- 公共系统可信、B1仍无净增量 → 关闭该实现，不把工程做无限长。
- B1有净增量但不支持账户10%/20% → 记录组件价值与缺口；申请新的独立收益假设，而非强行拼失败组件。
- Dev达标但压力或验证不通过 → 明确失败/脆弱，不宣布可实盘。

**最重要的三条纪律：** 实施者不能给自己签验收；工程通过不等于策略有效；没有达标者也必须诚实收官。
